# Agent 自进化策略优化设计

目标：让一次任务中学到的做法改善之后的新任务。判断依据是后续最终答案的正确性、完整性与证据支持；保存了经验、命中了经验、提示词变短都不等于获得了这个收益。实现进度与运行结果统一见 [progress.md](../../progress.md)。

## 策略：批量学习，分项管理，组合验证

采用“一批任务反馈 → 按问题机制和适用条件分组 → 多条条件经验 → 定向筛选与组合迁移对照 → 保留、修订或淘汰”。一次学习可以产生多条经验；每条经验分别记录来源、条件和版本，便于后续修订。一个完整程序可以包含多个相关步骤，不必拆成互相无法独立使用的碎片。爬山法只是提示词优化的可选工具，不作为这条学习链路的前提。

第一步复用现有 V1 单经验编译与隔离回放，分别编译多个候选并在预算内并行筛选，不要求一条走完整条流程后才开始下一条。筛选后对拟共同使用的经验做整包迁移验证，再接普通请求的选择和结果回流。单条对照是定位问题的工具，不是学习吞吐限制。经验可以通过上下文影响模型；关键在于它来自什么任务证据、何时适用、是否改善新任务。

## 当前链路的实际边界

| 环节 | 已有能力 | 对策略的约束 |
|---|---|---|
| 学习来源 | [reflection](../../evals/evolution_reflection.py) 读取执行片段和外部核查，按原因分流；仅方法错误进入候选 | 完成任务不会自动触发学习；成功程序没有正式入口。不能把成功或模糊措辞伪标成错误。 |
| 经验维护 | [registry](../../evals/evolution_experiences.py) 已有来源、条件、反例、父版本、冲突与撤回 | 这些机制可以复用。旧经验合并多个问题，难以分辨具体有效步骤。 |
| 经验应用 | [候选编译](../../evals/evolution_candidates.py) 将一条经验编译为完整方法；[在线选择器](../../stocksage-backend/src/main/java/com/stocksage/evolution/FundamentalsMethodRegistry.java) 在 baseline 与一份 staged 包之间选择 | Python 的 select_approved() 尚未接在线调用。V1 有意固定完整包，未实现按研究子任务选择多条经验。 |
| 适用条件 | [OrdinaryEvidence](../../stocksage-backend/src/main/java/com/stocksage/service/OrdinaryEvidence.java) 产生 fundamentals、报表期间、period-comparison 和合格证据标签 | 没有增长、现金流、流动性等子任务标签；自然语言 applicabilityBoundary 本身不执行语义判断。 |
| 使用反馈 | [observation](../../evals/evolution_observation.py) 按方法包汇总普通执行、外部质量复核和撤回建议 | 经发布包能追溯经验，但没有自动把结果送回该经验的修订流程。 |
| 效果验证 | [两阶段回放](../../stocksage-backend/src/main/java/com/stocksage/evolution/EvolutionReplayService.java) 执行清单指定的包 | 它绕过普通请求选择。指定方法是否有效，与在线能否正确选用，需要分别验证。 |

对[旧经验](../../evals/evolution/common-fundamentals-2025-v1/ai-experiment-001/experience.json)调用现有 load_record() 与 experience_matches() 的静态检查发现：其自身声明条件可以匹配，但无法匹配源码所产生的普通年度比较标签。未产生的条件是 historical-fundamentals 和 financial-statements。不能简单改名当作修复，必须确认真实证据满足其期间、科目与口径要求。该包没有上线，因此这是条件未贯通的证据，不是已经发生的线上故障。

历史效果只在原报告维护：[旧候选结果](../../evals/evolution/common-fundamentals-2025-v1/ai-experiment-001/README.md)、[当前 Max 基线](../../evals/evolution/common-fundamentals-2025-v1/max-experiment-20261001/README.md)。基线通过不能证明跨任务学习有效；旧候选失败不能证明所有经验学习无效。

完整草稿回放、真实经验生成和候选筛选的后续证据见[批量学习验证](../../evals/evolution/batch-learning-validation-20261002/RESULTS.md)。单题纠错、原有正确题是否退步、跨公司迁移和执行稳定性分别判断，不能用其中一项替代其他项。

## 学习什么、何时触发

复用现有字段，保存“条件—操作—限制”，不存公司答案，也不要求保存隐藏推理。例如，“同财年累计现金流还原单季”可以成为待实验的方法类型：先确认科目、单位、合并范围与累计起点一致，再用相邻累计值之差还原对应期间流量；比率从还原后的分子分母重算；资产负债表期末余额不适用。这个例子尚不是已经学到并验证的经验。

生成器可以对一组相关轨迹批量提出经验，每条保留自己的来源、条件、操作与限制。不同问题组可并行处理；同义经验合并，已有经验优先修订，互相冲突的经验不直接合并使用。若与当前方法没有实际区别，记录“不需要更新”；不把“以后仔细检查”当作方法，也不因保存次数多就提高可信度。候选数量由有效问题组和预算决定，不为达到数量而生成。

| 已核查观察 | 处理 |
|---|---|
| 明确方法错误，输入证据够用 | 针对该步骤提出或修订一条经验；同原因、同来源反馈合并，保留各自引用。 |
| 正常任务中出现可复核的成功程序 | 可形成学习假设；先检查是否只是已有规则。正式入口需要独立的成功反馈契约，不能复用 METHOD_ERROR。 |
| 缺数据、供应商失败、执行器错误 | 进入已有对应队列，不能让分析经验凭空补事实。 |
| 分析正确而最终回答失真 | 归到最终整合阶段，不能只改分析方法或将其算作分析经验失败。 |
| 仅有点赞、自评通过、请求成功 | 不足以触发方法更新。 |
| 没有可信新信息 | 保持现状。 |

初期保持显式批次运行，不必每次聊天结束都调用反思模型。成功结果只形成候选假设，仍要通过新任务对照；正式支持成功程序时，须同步版本化反思、经验校验与注册入口，不能只放宽一个枚举。

## 新结果怎样改变经验

沿“实际 bundle ID/hash → 发布包 → experience hash/version”关联现有记录。外部复核区分：没选中、条件不满足、方法未按要求执行、方法本身有反例、后续整合出错。只有定位到经验的问题，才缩小适用范围、生成带父版本的新经验或撤回；不能因一次供应商失败删除好经验。

成功提供支持材料，明确反例提供修订材料；成功率本身不证明因果收益。单经验候选复用现有映射，组合包需显式保留全部经验及版本的清单。组合收益只归属于该组合，不自动证明每条经验都有独立贡献。整包退化时先保留基线，再根据失败任务和适用条件排查，必要时移除某条经验重跑相关开发题；不预先穷举所有经验组合，也不因一个题错就判整批经验都无效。

## 怎样判断输出质量

在用分数自动筛选新经验前，先统一评价执行：复用并版本化现有 rubric，固定逐项通过／失败／不可判定规则、评审输入模板、实际评审模型与参数、输出字段和汇总口径。用独立于候选调优的已核实样本校准评审，检查错误漏判、正确答案误判、歧义处理和重复评分一致性。评分脚本只校验外部标签，或不同 AI 按文字规则复核，都不能单独证明评价体系已经校准；历史实验保留其原始标准及结论，新标准下的重评另存并对两臂一致执行。

先定义一题怎样算完成，再看答案。每题依据真实需求和权威源材料登记必答项、事实与计算口径、允许的推断和证据不足时的合理回应；不要求模型逐字复述参考答案，也不临时增加用户未问的任务。

| 检查 | 判断依据 | 自动化边界 |
|---|---|---|
| 任务完成 | 要求的比较、计算、解释是否答齐，是否无必要地拒答 | 程序核对结构化必答项；自然语言是否真正回答仍需复核。 |
| 事实与计算 | 公司、科目、期间、币种、单位、原值、公式与结果 | 有可靠结构化抽取后用确定性计算校验；程序不能只凭数字相同确认科目和期间正确。自行增加的数字也要查。 |
| 证据支持 | 关键主张与实际可见来源相符，引用确实支持该主张 | 程序可校验引用身份和引文存在；语义支持不等于字符串命中，须另行判断。 |
| 分析价值 | 完成预先列出的解释要点，结论与证据相称，处理影响判断的反向证据 | 依据具体要点评审；不按篇幅、措辞华丽或“像专家”评分，不以全部回避判断换取少错。 |
| 不确定性 | 已知事实、条件推断和未知项区分清楚，限制约束相应结论 | 结合任务和材料判断；无数据时承认未知，数据足够时不能滥用未知。 |

对可评价的回答，核心必答完整且无实质错误才记通过。错期间、错科目、错数量级、无依据的关键因果和遗漏核心要求分别记录；轻微舍入与存在合理解释的措辞歧义不直接等同于事实失败。缺输出、评审不足或证据冲突保留不可判定。完成率、可评价率与质量结果一起报告，失败和未知请求不能从总尝试数中消失；不能把所有失败统一叫作幻觉。

判定使用“确定性核验 + 带证据的语义复核”。语义评审须给出答案片段、对应原文及理由，尽量隐藏版本身份并打乱展示顺序；第二次复核优先覆盖争议、严重错误和少量已通过样本，避免只检查判失败的题。抽取模型和复核模型都可能漏项，换一个模型也不自动产生独立真值。用已核实的通过、失败和歧义样本检查评审的一致性、误判与漏判；修改标准时保留版本并重审两臂。

模型评审存在位置、长度及自偏好等偏差，不能作为唯一真值，相关实证见 [LLM-as-a-Judge](https://arxiv.org/abs/2306.05685)。[Agent 评测实践](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)也区分最终结果与执行轨迹：最终结果用于判任务是否完成，轨迹用于定位原因。开发阶段可以按现有授权执行 AI 交叉核查，结论明确标注 AI 评测，不伪造人工校准。

现有 [evolution_quality.py](../../evals/evolution_quality.py) 已有来源与答案绑定、数值、引用、必答项和拒答检查；四维语义质量仍依赖外部复核，不是全自动真值判定器。冻结事实以外的额外数字依赖完整抽取和支持性复核，程序不能自动发现所有漏抽取的主张。现有四维通过率以已评 PASS/FAIL 为分母，展示时必须同时给出缺评数和覆盖率，不能用局部通过率代表全部任务。该检查逻辑、已冻结实验标准与本文拟定的评审流程需明确区分；此处不改写历史标准。

## 怎样判断进化有效

项目评测入口统一在 [evals](../../evals/README.md)，各对象独立维护标准。检索和 RAG 回答检查由 [run_retrieval_eval.py](../../evals/run_retrieval_eval.py)、[run_rag_eval.py](../../evals/run_rag_eval.py) 与 [run_ragas_eval.py](../../evals/run_ragas_eval.py)负责；基本面进化的两阶段标准由 [evolution_rubric.py](../../evals/evolution_rubric.py) 定义，[evolution_quality.py](../../evals/evolution_quality.py) 直接绑定实际分析和最终回答阶段。普通回答保留自己的标准，两者只复用 [eval_common.py](../../evals/eval_common.py) 中的哈希、证据绑定和复核格式检查。证据支持、数字正确和任务覆盖属于回答层指标，不能替代过程与进化指标。

项目另有 [规划／路由评测](../../evals/run_agent_eval.py)和[普通执行评测](../../evals/run_ordinary_live_eval.py)，分别检查计划、路由及真实 Trace 中的工具调用、参数、结果等。评估完整 Agent 时，按受影响路径分别提供过程、回答和迁移对照的证据；没有执行的部分明确记为未验证，不用 RAG 得分或回答通过率替代。

绝对质量回答“现在会不会做”，进化对照回答“是否因为这批经验而做得更好”。在未参与学习和筛选的新公司／报告任务上比较进化前后，固定实际模型、基础提示模板、数据快照、工具权限与推理预算，只改变学习制品。最终回答是主要终点，分析稿及经验命中是原因定位信息。

- **修复与回退：** 同题列出原有实质问题修复了哪些、新增了哪些；两者都有时记混合，不能只展示修复案例。
- **新任务完成率：** 对同一批可评价的任务计算完整通过比例及变化，同时单列不可判定和执行失败。不能靠删除困难任务、减少必答内容或无必要拒答提高成绩。
- **能力保留：** 按任务类别查看回退，无关任务和原有普通能力作为回归对照，避免总平均掩盖某类退化。
- **迁移与稳定性：** 公司、原报告家族分开统计；相同报告改写的多个问题及同题重复不当成独立公司样本。必要重复估计运行波动；小样本先报告逐题证据，不把一次胜出称为稳定提升。
- **成本与时延：** 记录两阶段实际用量和完成时间，生成、筛选与复核成本另计。质量相当但开销下降属于效率收益，不能替代研究能力提升，也不能忽略学习过程的成本。

不只生成一个加权总分。候选若在预先声明的主要指标改善、关键能力不退步且预算可接受，才进入保留阶段；两臂打平或差异不足时允许“无改善／证据不足”。批量经验的整包对照证明组合效果；单条独立贡献需有相应移除对照，不能从整包胜出推断。

现有 [decide_comparison](../../evals/evolution_acceptance.py) 已按报告组计算配对指标和区间，检查关键项不退步，并以最终阶段决定正式质量改善；正式门槛来自冻结 policy，不在本文另设一套百分比。共享控制组、样本不足和非盲 AI 评审均须披露。换模型或手工改全局模板的提升单独归因，不能计入经验学习收益。

固定证据回放只证明回答阶段的效果。要声称整个 Agent 进化有效，还需普通执行验证：是否选中适用经验、是否取到所需数据、工具是否按预期执行，以及最终任务是否成功；检索命中率或经验命中率本身都不能代替最终质量。

## 首个迁移实验

问题：从一批正常财报任务形成的条件经验集合，能否改善未参与学习的新公司任务，同时不损害原有能力及不适用任务？

1. **冻结正常任务。** 覆盖多种普通需求，例如累计财报还原单季、现金流与利润对照、债务和流动性口径。学习／开发材料与新公司迁移任务分开，保留无关任务及边界任务。按产品需求选题，不看基线对错后筛题；不使用现有 HOLDOUT，不把已看过的 VALIDATION 改名为未见确认集。
2. **批量核查并分组。** 运行当前 Max 的两阶段基线，根据原表及确定性计算定位实际问题，按机制和适用条件分组。当前纠错契约下，有明确方法错误的组可进入候选；某一组无错误不阻塞其他组。成功程序保留为学习材料，待成功反馈契约版本化后另行登记实验，不能伪造失败或临时绕过入口。
3. **分别生成与编译。** 多组独立处理，复用 build_experience、experience_matches、compile_candidate、export_eval_bundle。现有 reflection 每次产出一条，可由批次编排多次调用，不必先改变它的返回契约。条件写入共同评测的完整方法正文；核对候选与 baseline 的差异和经验来源，避免无关重写。并行只改变调度，不改变每个候选的身份与审计记录。
4. **定向筛选。** 每个候选先跑其相关开发题、少量不适用题和共同基础回归，不要求每条经验都重跑全部数据。同一批次、相同构建、输入、模型参数与评估规则下可共用基线结果，但不复用旧模型或旧模板的基线；交错安排控制组与候选以观察时间波动。共享控制组的比较不是独立重复试验。筛选是开发诊断，不替代正式验收。
5. **冻结组合再验证迁移。** 入选经验去重并检查冲突，编译为一个显式列出全部经验版本的固定包。在未参与筛选的新公司任务上，对照 baseline 与组合包，新上下文、同题相邻、跨题轮换顺序。不得额外携带学习对话或增加工具预算。组件实验让组合包也回答不适用题，验证条件是否被遵守；选择机制另测。个别通过不代表组合通过，整包通过也不代表每条均有独立贡献。
6. **按结果保留或定位。** 主要看最终答案，逐题记录修复、新增问题、混合或打平，必答完整性不得退步。只在出现退化、冲突或需要减少冗余时做定向移除对照，不把逐条完整归因作为整批学习的前置条件。反例用于新轮开发；修改后换新确认任务，不能在同一确认集反复调优并声称独立验证。

调用预算按实际问题组登记，不沿用单经验实验的 29 次上限。若开发基线有 N 题，第 i 个候选使用 n_i 道定向题，组合确认有 M 题，则每臂每题各运行一次“分析→最终”时，评测调用为 2N + 2Σn_i + 4M；生成、复核、必要重复和额外控制调用单列。这只是预算公式，不是已执行或性能提升的承诺。并行度受供应商容量与冻结预算约束；未知调用不自动重试。

现有 V1 候选只绑定一个 experienceRecordSha256，不能把多条经验拼接后冒充单条，也不能默认为单条候选的正式资格覆盖组合。独立候选筛选复用现有实现；[组合诊断编译器](../../evals/evolution_batch.py)以独立制品固定成员版本、哈希、顺序、条件和整包身份，并导出到既有隔离回放契约。它只接受本地提议经验，不授予正式资格；若后续接入已注册经验，成员被撤回时依赖它的组合也须停止使用，重新验证替代组合。正式支持还须同步更新编译、校验、发布和契约；本轮[批量实验](../../evals/evolution/batch-learning-20261002/README.md)不引入新的经验服务。执行期限、思考预算与评审协议的修复依据见[修复验收](../../evals/evolution/batch-repair-20261002/RESULTS.md)。

两臂只能说明所学制品是否有用。若要声称任务经验学习优于通用提示词维护，须增加不接触学习轨迹、同预算的通用方法更新对照；本轮不作这个更强主张。

## 迁移有效后再接系统

1. **统一真实条件。** 从已验证经验的前提出发，确认取证链能产生哪些可信条件；只增加该经验需要的字段。不能仅凭问题含“现金流”就声称比较期齐全、口径一致。
2. **接结果回流。** 复用 observation、发布包到经验的映射、父版本和生命周期，将核查后的反例变成新轮 DEVELOPMENT 材料，保留旧评测历史；初期仍可批次执行。
3. **应用经验证的经验集合。** 批量学习与在线应用数量分开处理：同一任务可以使用已经共同验证的多条经验。初期沿用一个固定组合包，通过其中的明确条件限制适用范围；实际需要按任务选择不同组合时，再扩展单 staged 包。不能在线任意拼接未经共同验证的组合；扩大范围须更新 V1 契约与匹配回归。
4. **按故障阶段扩大可学习对象。** 当前只改分析方法，无法学习取证顺序、工具调用程序或最终整合方法。实际证据若指向取证，才增加已有只读能力上的证据需求与取证步骤；若指向最终整合，则单独验证该阶段。不能在分析正文里加几句要求，就宣称这些模块也会进化。

提示词爬山、效率目标、向量经验检索和自动调度均不是首轮必要工程。正式资格、发布与激活继续遵守 [V1 契约](../evolution/evolution-v1-contract.md)，AI 诊断不冒充人工验收。策略模块一旦改变，登记新的评估器和执行身份，不改写旧报告的哈希或结论。
