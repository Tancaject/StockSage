# StockSage Agent 自进化实施计划

**版本：v1.0｜编制日期：2026-09-27｜状态：待实施**

**首期目标：普通 FUNDAMENTALS 路线的受控方法进化**

让系统从可核验的失败与评审中生成研究方法候选，在同一模型、同一证据和同一预算下比较，只有通过独立验收的版本才能供后续任务使用。

# 1. 首期范围与代码基线

## 1.1 只开放一条明确的改进路径

V1 只优化普通 `FUNDAMENTALS` 路线中 `FundamentalsAgent` 的方法文本，以及由已批准方法经验构成的有界上下文。普通路线的最终回答仍走既有流程，最终回答提示词保持固定。验收既检查领域报告，也检查最终用户回答，避免中间报告变好、最终答案却丢失关键结论。

V1 不改变路由、工具选择、原始数据、证据有效性判定、模型配置、Skill 执行结构、DEEP 辩论、评级策略或用户权限。缺少数据能力的问题进入普通开发缺陷队列，不能靠提示词“补出”不存在的数据。

## 1.2 已核对的事实及实施影响

| 代码事实 | 对计划的约束 |
|---|---|
| `FundamentalsAgent.analyze(query, context)` 使用无工具客户端；方法提示分散在该类和 `AgentConfig`。[S2][S3] | 先做零行为变更的提示词外置，再增加受控的方法候选。 |
| 普通路线由后端取证、领域分析、最终回答构成。[S4] | 回放必须调用真实 Java 组件，不能用另一段 Python 提示词模拟原系统。 |
| DEEP 采集器直接将各维度快照写入 `AnalysisState` 的报告字段。[S5] | 不因字段名含 Agent 就假定调用了普通领域 Agent；V1 收益不得宣称覆盖 DEEP。 |
| Skill 仅有确定性 CAPABILITY 步骤，注册表在启动期加载不可变清单。[S6] | 研究方法 Playbook 与执行 Skill 分开，不开放运行时任意注册。 |
| Research Memory 来源为报告版本，包含建议与来源信息。[S7] | 方法经验使用独立类型与生命周期，不混入历史投资结论。 |
| 普通 live runner 检查执行契约，答案质量字段为 `NO_DATA`。[S8] | 增加独立质量评估；接口成功、引用 ID 合法都不是事实正确的充分证据。 |
| 报告复用哈希包含固定提示词契约版本，而不是未来的动态方法包。[S9] | 新增版本必须进入自身缓存键；后续接入 DEEP 时再改其报告复用与 checkpoint 契约。 |

## 1.3 实施前重新核对

E00 必须检查工作区实际 HEAD、未提交改动和上述调用链。若代码已变化，记录差异并调整接入点，不强制回退到本基线，不覆盖已有工作。历史 TODO 与设计文档仅供参考，实际实现以当前代码与运行证据为准。

# 2. 目标架构与不可变边界

## 2.1 在线执行与离线进化分离

```text
在线：请求 → 后端取证 → FundamentalsAgent → 固定最终回答流程
                         ↑
                  已批准的不可变方法包

离线：执行快照 + 外部评审 → 失败归因 → 方法经验候选
                                     ↓
                               提示词/方法包候选
                                     ↓
                       隔离回放 → 独立比较 → 人工批准
                                     ↓
                             受控发布 / 撤回
```

方法包负责“怎样分析证据”，不是证据本身。方法中的示例不能被赋予 `[E1]` 等本轮证据编号，也不能成为新财务数字的来源。历史 Research Memory 继续使用既有机制；V1 实验默认关闭其注入，必须需要时才使用两组完全相同的冻结快照。[S7]

## 2.2 九项强制边界

1. **权限不进化。** 优化器不能修改 `CapabilityPolicy`、认证授权、只读限制、网络允许列表和运行硬预算。
2. **裁判不进化。** 当前实验中的验收代码、评分规范、标签、数据集切分与发布门禁不能由候选生成器修改。
3. **证据不进化。** 不改写原文、财务字段、证券身份、来源版本、时间信息或原始哈希来提高得分。
4. **每轮只改一个组件。** 首期只改 `fundamentals.method`，其他角色、模型、采样参数和工具执行保持固定。
5. **一次任务固定一个包。** 入场时解析具体方法包版本；执行中不读取可变化的 `latest`。
6. **候选不进入生产。** 未发布候选只在隔离实例运行；普通用户不得指定候选 ID、任意提示词、文件路径或模型参数。
7. **实验不得污染记忆。** 回放不写正式报告、会话消息、Research Memory 或生产向量索引；实验输出进入独立命名空间。
8. **无数据不是通过。** 缺账号、缺标签、缺模型响应、未跑完或评估器故障必须有明确非通过状态。
9. **发布与生成分权。** 优化器只有候选与实验权限；正式激活需要人工批准和受保护发布流程。

## 2.3 控制面权限

建议设置 `EVOLUTION_OPERATOR`、`EVOLUTION_REVIEWER` 两个逻辑权限。V1 可映射到现有管理身份，但候选生成进程不能获得发布凭据。独立保留集放在评测者可读、优化器不可读的位置；仅把“角色名字不同”当作隔离不合格。

# 3. 阶段总览与依赖关系

| 阶段 | 步骤 | 核心交付物 | 阶段放行条件 |
|---|---|---|---|
| P0：冻结基线 | E00—E01 | 基线清单、范围契约、变更允许列表 | 代码接入点、边界、责任明确 |

## 3.1 依赖图

```text
准备：E00 → E01
版本分支：E01 → E02 → E03
数据分支：E01 → E04 → E06
回放合流：(E03 + E04) → E05
基线合流：(E05 + E06) → E07
离线进化：E07 → E08 → E09 → E10 → E11 → E12
发布复验：E12 → E13 → E14 → E15 → E16 → E17
```

E05 同时依赖 E03 和 E04；E07 同时依赖 E05、E06。E11 必须复用已通过的回放器和评估器。未通过 E12，允许整理实验结果，但不得进入生产激活。

## 3.2 任务执行规则

每步使用独立小提交或可清晰回退的提交组。状态使用 `TODO / IN_PROGRESS / BLOCKED / DONE`。`DONE` 仅代表该步骤验收已完成，不代表整套自进化已经成功。证据不充分时写 `BLOCKED` 或实验 `INCONCLUSIVE`，不得修改标准凑通过。

必须交付：改动文件、执行命令、退出码、测试结果位置、未执行事项、风险与回滚方法。脚本存在不算跑过；mock 测试通过不算 live 通过；候选分数高于基线不自动等于可发布。

## E03｜不可变方法包、运行身份与缓存隔离

**前置：** E02。**负责人：** 后端。**状态：** TODO。

1. 定义 `AgentPolicyBundle` 与 `EvolutionRunContext`，具体字段见第 14 章。内容规范化后计算哈希，发布内容不可原地覆盖。

**回滚：** 新请求切回 `baseline-v1`；已开始的请求保持原固定版本，禁止中途静默换包。

# 6. P2：证据快照与真实回放

## E04｜建立可审计数据集与快照

**前置：** E01。**负责人：** 评测/数据。**状态：** TODO。

**实施步骤：**

1. 先建立 12 例 smoke 集用于验证机制；建议首轮研究集从 120 例起步，按组切成开发 60、验证 30、保留 30。数字是规划起点，不是可靠性证明。
2. 按“发行人 + 报告家族 + 问题变体”分组防泄漏；同一原文的改写、翻译、相邻问题不得跨集合。至少保留独立发行人与期间的挑战样本。
3. 每例保存原始证据、模型实际可见的有界证据、来源版本、业务期间、发布时间与可用时点、单位币种、输入问题和必要历史；只存哈希而不存内容不能回放。
4. 将答案期望、错误标签、必答事实与评分规范放入独立 gold 文件，不装进 Agent 请求。保留集只交独立评测者。
5. 包含正常数值、零值、负值、缺值、季度/累计、币种单位冲突、重述、标的混淆、旧证据及恶意文档指令等样本。
6. 私有数据须授权和脱敏；无法确认使用范围的样本排除。模型生成的合成案例标注 `SYNTHETIC`，不冒充真实业务效果证据。

**交付物：** JSONL 清单、快照目录、切分清单与哈希、独立标签、数据来源说明。

**验收：** 内容哈希校验通过；无跨集合近重复；Agent 输入中没有 gold；关键样本有人工复核记录。

**回滚：** 数据集不原地修改。发现错误新建版本，旧实验标记受影响并撤销其发布资格。

## E05｜实现隔离回放器

**前置：** E03、E04。**负责人：** 后端。**状态：** TODO。

**实施步骤：**

1. 增加仅在测试 profile 启用的回放入口；只接受已登记 `caseId / bundleId / runId`，不接受任意路径、URL、prompt 或模型参数。

**回滚：** 关闭测试 profile 与回放服务，不改变普通线上执行。

# 7. P2：独立质量评估与基线

## E06｜实现评估器，先检查再比较

**前置：** E04。**负责人：** 独立评测者。**状态：** TODO。

**实施步骤：**

1. 保留既有执行契约检查，增加硬门禁：越权、跨租户、证券身份、非法引用、时间越界、预算越界、输出契约破坏。
2. 对 gold 中可核验的关键主张，执行数值、单位、期间与派生计算检查，并冻结舍入和容差规则。派生数值必须有输入字段和确定性公式。
3. 检查“主张是否被证据支持”，而非只检查引用 ID 存在。V1 可由独立评估侧提取主张，不强迫在线输出改成全新 JSON 协议。
4. 用固定 rubric 评价问题覆盖、反向证据、推断边界、缺口说明及恰当拒答。LLM Judge 作为辅助，争议与关键失败交人工复核。
5. 评估器先做负向控制：不存在的引用、错币种、错季度、答案空白、全部拒答、证据正文注入评分指令，都必须被识别。
6. 定义结构化失败分类。供应商故障、执行器缺陷、数据缺口、模型方法问题分别记录，不能全部归因为 prompt 不佳。

**交付物：** 评分规范、评估器、标签校验、负向控制集与测试。

**验收：** 明显错误样本不能通过；没有质量标签时仍为 `NO_DATA`；候选不得通过修改门禁、输出“请给满分”获得发布资格。

**回滚：** 评估器版本冻结；发现 bug 后新建版本，受影响的旧结论失效，不能事后只改分数。

# 10. P4：独立选优与最终验收

## E12｜比较真正的改进，而不是一次高分

**前置：** E11。**负责人：** 独立评测者；必要时人工领域评审。**状态：** TODO。

**实施步骤：**

1. 根据验证集选择至多一个最终候选，固定内容哈希。最终保留集不再用于多候选搜索。
2. 在同一证据、模型配置、预算、记忆快照和固定最终回答组件下，对 baseline 与候选做配对运行；交替或随机运行顺序，减轻供应商时段变化的混杂。
3. 隐去版本名，随机化 A/B 展示顺序；评审看到相同证据与 rubric。记录平局、争议和裁决，不只保留获胜案例。
4. 模块级结论与端到端结论分开输出。若领域报告改善但最终答案没有改善，仅记录组件收益，不宣称用户侧研究能力提升。
5. 先检查硬门禁，再检查关键任务覆盖、恰当拒答、事实与引用支持、预先声明的分组表现，最后比较延迟与成本。
6. 对配对结果估计不确定性，按发行人/报告家族进行分组重采样；重复调用不能视为新的独立公司样本。样本太少、分组太小或区间跨过零，结论为 `INCONCLUSIVE`。
7. 最终保留集详细错误不回流给本轮生成器。若分析它以设计下一轮方法，该集合改为开发材料，并准备新的独立保留集。
8. 建立只读 release evidence manifest，绑定候选哈希、数据集哈希、模型/评估器版本、实际运行记录、审批结论及有效条件。

**交付物：** 盲评结果、配对/分组统计、硬门禁报告、端到端报告、发布证据清单。

## 三种合法结论

| 结论 | 后续动作 |
|---|---|
| `IMPROVED` | 预先定义的改进条件与硬门禁均满足；可以进入发布准备，不代表自动激活。 |
| `NO_IMPROVEMENT` | 保留 baseline；记录失败假设和候选结果，结束本轮。 |
| `INCONCLUSIVE` | 证据不足；保持 baseline。另行授权补样本，不修改门禁凑通过。 |

**验收：** 没有空缺样本被当成通过；成本比较包含所有相关模型调用；“全部拒答”“超长模板”“只迎合 Judge”不能获得发布资格。不存在满足条件的候选时，结束本轮也是验收合格的工程行为。

**回滚：** 尚未改生产，无线上回滚。若评估器发现缺陷，撤销 release evidence 资格，并对受影响候选重新评估。

V1 工程完成必须具备：可固定运行版本、可隔离回放、可检查质量与边界、可有界产生候选、可独立选优、可人工发布与回滚。V1 效果成立另需有通过独立验收的改进证据；工程完成不保证效果成立。

## 后续只按独立切片扩展

| 扩展顺序 | 开放内容 | 新增前置条件 |
|---|---|---|
| V2-A | 普通 NEWS 方法进化 | 事件时间/发布时间标签、转载去重、因果表达与来源支持评估 |
| V2-B | 普通 MARKET 方法进化 | 行情时区、盘前盘后、延迟标记、指标计算与缺口的确定性检查 |
| V2-C | 检索与证据选择参数 | 冻结语料/索引而非固定检索结果；独立 Recall、排序与最终质量评估 |
| V3 | DEEP 续停、补证与方法改进 | 对真实 DEEP 调用链单独建回放；bundle 进入报告哈希、checkpoint 与恢复契约；评分和评级先冻结 |

# 14. 核心契约：版本、状态与缓存

以下结构均为建议新增契约，不是现有类的准确字段清单。实现时统一使用严格 Schema，拒绝未知字段，不以任意 Map 穿透业务边界。

## 14.1 不可变方法包

```json
{
  "schemaVersion": 1,
  "bundleId": "fundamentals-method-v1-candidate-001",
  "parentBundleId": "fundamentals-baseline-v1",
  "scope": {"route": "FUNDAMENTALS", "role": "FUNDAMENTALS"},
  "fixedContractVersion": "fundamentals-contract-v1",
  "methodArtifactRef": "methods/method-001.txt",
  "experienceVersionRefs": ["experience-001@1"],
  "requiredCapabilities": [],
  "contentSha256": "<由规范化实际内容计算>"
}
```

`methodArtifactRef` 由可信加载器解析登记资源，不是运行时任意路径。方法包哈希不包含会自引用的哈希字段，也不包含审批状态；审批、实验结果与部署状态通过独立记录绑定该哈希。相同 bundle ID 不允许覆盖不同内容。

## 14.2 运行身份与缓存键

`EvolutionRunContext` 至少包含：`runId / experimentId / caseId / repeatId / gitSha / bundleHash / modelConfigHash / evidenceSnapshotHash / historySnapshotHash / memorySnapshotHash / fixedFinalPromptHash / evaluatorVersion / runMode`。

分开定义两种身份：业务内容身份表示相同输入，执行身份还包含 repeat ID。评测默认关闭模型答案缓存；不得因为内容身份相同就跳过重复调用。部署侧若存在答案缓存，必须包含方法包与模型配置身份。

模型使用可变化别名时记录实际可获取的 model/version/fingerprint；供应商无法暴露不可变版本时，标为可重复性限制，使用同期配对运行，不宣称完全确定性复现。

## 14.3 状态机

```text
候选：PROPOSED → VALIDATED → EVALUATED → SELECTED
           └────────────→ REJECTED
发布：DRAFT → APPROVED → SHADOW_PASSED → ACTIVE → REVOKED
实验：CREATED → RUNNING → COMPLETED
                       ├→ BLOCKED
                       ├→ BUDGET_EXHAUSTED
                       └→ CANCELLED
```

实验 `COMPLETED` 后另有 `IMPROVED / NO_IMPROVEMENT / INCONCLUSIVE` 结果。没有样本、缺标签、运行未完成，不得填 IMPROVED。所有状态转换有 actor、时间、前状态、原因与关联证据；ACTIVE 必须同时满足 E12、E14、E15，不仅是文本上的 APPROVED。

# 15. 数据、时间与经验治理细则

## 15.1 样本与标签物理分离

执行侧只取得问题、历史上下文、可见证据及必要的时点约束。评估侧额外取得正确字段、必答主张、预期澄清/拒答条件、禁止推断与人工标签。开发阶段优化器可看到开发反馈；验证结果限定用于选优；最终保留集不得挂载进优化器容器或工作目录。

证据快照必须同时保存原始内容和实际进入模型的内容，区分“原文里有”和“模型真正看到”。上下文被截断时要记录截断策略、范围和哈希；不能在评估时用隐藏的完整正文要求模型知道被移除的信息。

## 15.2 时间字段不能互相替代

| 字段 | 语义 |
|---|---|
| `periodStart / periodEnd` | 数字或披露对应的业务期间 |
| `publishedAt` | 原始来源正式发布时间 |
| `availableAt` | 该来源版本在目标研究条件下可使用的最早时点 |
| `retrievedAt` | 本系统实际取得该版本的时间 |
| `sourceVersion` | 原始、修订或重述版本身份 |
| `reportGeneratedAt` | 研究报告生成时间，不代表证据变新 |

当前 Research Memory 的捕获逻辑把报告生成时间写入 `dataCutoffAt`；设计文档也明确该时间不是底层证据的严格业务时效。[S7][S10] V1 为新评估快照保存独立字段，不顺带重构现有记忆排序。缺少发布时间/可用时点的案例可以用于当下证据约束测试，但不得冒充严格历史 as-of 回测。

即使工具快照被冻结，模型可能从预训练中知道某些历史结果。首期只评价给定证据下的研究质量；不能仅凭冻结数据就宣布历史预测无泄漏。

## 15.3 经验字段与冲突

每条经验保存：`experienceId / version / scope / trigger / prerequisites / method / forbiddenInferences / sourceRunIds / feedbackRefs / counterexamples / validationRefs / status / contentHash`。

两条方法发生冲突时，不让模型在运行中任意挑选。优先细化适用条件，再按已批准版本构造显式方法包；尚未验证的冲突条目不发布。`helpfulCount`、点赞或模型自评可作观察值，不是发布门禁。

## 15.4 隐私与删除

真实用户样本默认用户隔离，不直接转换成全局经验。删除请求需要覆盖实验快照、派生候选中的可识别内容与索引；必要时撤回关联方法版本。审计可保留不含私人正文的哈希、状态与撤回原因，不能以“可追溯”为由永久保存无授权敏感内容。

# 16. 指标与发布门禁

## 16.1 不使用一个总分掩盖严重错误

| 指标 | 定义与注意事项 |
|---|---|
| 硬门禁违规 | 越权、跨租户、非法来源/标的、未来信息越界、突破固定预算；测试中出现任一即不发布 |
| 数值正确性 | 金标准主张中数值/单位/期间/币种/派生公式正确的比例；不存在适用项记 N/A，不填满分 |
| 引用支持率 | 被引用证据真正支持的可核验主张数 / 可核验被引用主张数；仅 ID 合法不够 |
| 任务覆盖率 | 正确回答的必答要点 / 适用必答要点；用于惩罚空泛或全部拒答 |
| 恰当拒答 | 分开统计应拒答案例的正确拒答和可回答案例的不必要拒答 |
| 配对质量差 | 固定 rubric 下同案例候选减基线；按预先确定的任务权重汇总 |
| 成本与稳定性 | 领域、最终回答、反思和 Judge 分项用量；在线与离线成本分开，均计入实验总账 |

模型评审需接受固定格式和证据约束；输出解析失败就是评估故障。关键财务事实优先程序核验/人工标签，不以另一个模型“觉得正确”替代原始证据。

## 16.2 E07 冻结的门禁字段

实验 manifest 必须声明：主指标、最小有意义改善 `minMeaningfulDelta`、关键分组、可接受的非退化界限、成本/延迟上限、重复次数、抽样规则与统计方法。取值依据业务目标和基线波动确定，必须在搜索前冻结；本文不伪造通用的收益阈值。

建议首轮采用保守规则：硬门禁零违规；关键已标注事实错误不增加；端到端任务覆盖和恰当拒答不退化；主指标配对差达到预先声明幅度，且按案例组计算的不确定性区间下界大于零；成本与延迟符合上限。样本不足以支持这些判断时输出 INCONCLUSIVE，而不是随意降低标准。

“测试中零违规”只代表测试覆盖范围内未发现，不是线上绝对安全保证。尚无足够样本的市场/任务类型不得扩展适用范围。

## 16.3 运行失败如何计入

候选自身超时、格式错误、空答案、超预算应计入其失败，不从分母删除。基础设施故障若影响配对公平性，整对标记无效并按预定重试规则重跑，仍保留原始失败与成本。未完成整个清单不得报告完整通过率。

## 16.4 验收证据等级

`STATIC_REVIEW` 只说明读过代码；`UNIT_TEST` 说明受控断言；`SNAPSHOT_LIVE_MODEL` 说明固定证据下真实模型运行；`END_TO_END_REPLAY` 说明真实组件串联；`AUTHORIZED_LIVE` 说明授权环境现场验证。报告必须写明等级，不能用低等级替代高等级。
