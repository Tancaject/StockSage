# Agent Evolution V1 契约

范围依据为 [用户的实施计划](implementation-plan-v1.0.md)，当前接入点见 [基线](baseline.md)。实现进度与验收结果只在 [progress.md](../../progress.md) 记录。

## 唯一可变对象

一次 V1 自动进化实验只改变普通 FUNDAMENTALS 分析师的 `fundamentals.method`。角色职责、事实边界、输出章节、用户任务模板、路由、工具、模型参数、最终回答系统规则和 DEEP 在该次实验中均保持固定。`baseline-v1` 是当前程序的内置默认包名，其实际内容由随程序发布的提示词资源决定。

经验作为离线候选生成的素材与来源记录。每个候选在评估前编译成完整方法正文；V1 不在执行时另外选择、追加尚未共同验证的经验。固定契约和方法内容一起绑定到包哈希，内容变化必须产生新身份。E13 的发布只封装已验内容，不能重新组装方法。

`AgentPolicyBundle` 的方法文本上限为 2,000 个 Java 字符。输入证据不能为了容纳方法而被悄悄裁减；实际输入超限时回放失败。结构与长度校验不证明自然语言方法一定遵守事实规则，后续仍须执行独立质量和越权负例验收。

生产注册表保留 `baseline-v1`，仅在启动时加载应用拥有、经发布者签名且固定哈希的批准包。批准包进入普通请求还需要独立的激活授权，并匹配服务器确认的账号、适用条件与运行身份。评测 profile 可在启动时从操作员登记文件加载实验包，形成单独的不可变清单；该清单不会修改生产注册表。未知 ID 或契约/内容哈希不匹配均拒绝。HTTP 请求不能提供方法、路径、模型配置或动态代码。候选对象的合法构造不代表已批准，更不会自动加入生产注册表。

## 身份与实际输入

一次普通执行固定一个不可变方法包，方法身份绑定同一 Trace 中的分析阶段与最终阶段。实验使用独立 `runId`，每次重复调用也必须有独立执行记录。

执行清单提前登记 `runId / caseId / bundleId / repeatId`。HTTP 只接收前三项并严格匹配登记组合；进程内失败或超时也消费该 runId。SQLite 实验账本可保留已提交/完成/未知记录供可信编排器恢复，不自动重试未知调用；单独使用 HTTP runner 不提供跨重启去重。两种路径都不保证远端推理恰好一次。

区分固定最终系统规则哈希与实际完整最终输入哈希。候选分析稿改变时，完整最终输入必然变化。记录分析师与最终回答各自实际输入、输出、可见证据、模型参数、响应模型、用量与状态。不可获取的供应商信息保留未知，不能推测。

普通代码维护可以修订系统模板，但修订后须按新的完整身份建立比较基线，不能继承旧构建的候选资格或效果证据。`bundleSha256` 绑定实际方法；`fixedContractSha256` 只绑定基本面固定系统与任务模板；`fixedFinalPromptSha256` 单独绑定最终回答规则。比较还须匹配构建、模型、记忆等运行条件，不能仅凭相同的 `baseline-v1` 名称判为同一基线。

分析师使用已消歧 `resolvedQuery`，最终回答保留原始 `query` 和冻结历史。两组的源快照相同仍不保证最终可见证据相同；上下文预算或裁减造成实际可见证据变化时，不能纳入纯方法收益的配对比较。

## 数据与评估

开发、验证、保留集按发行人/报告家族与原文关联分组；问题改写不产生独立原文。执行输入只含问题、历史与可见证据；gold、原文隐藏部分和评审不能进入 Agent 输入。

12 例 `SYNTHETIC` smoke 只验机制，其语义标签初始为 `NO_DATA`，人工复核状态为 `UNREVIEWED`。不能据此宣布真实业务收益。研究集与独立评审未就绪前，E07 不能通过，E08—E12 的候选优化与选优不得宣称已完成。

按用户“先完成离线实现，真实验收后补”的安排，允许先验证候选制品、预算恢复和配对比较的代码机制。生成与实验库的 E07 门禁回调必须由可信编排器调用 `require_gate()`，验证独立评估者签发的基线、冻结策略与评估器指纹；空回调不是批准。`UNIT_TEST` 制品不能放行真实优化。授权源快照、独立 gold、两阶段评审、盲评与签名门禁使用[离线工作流](../../evals/evolution/README.md)中的绑定契约；真实数据集、评审校准和效果判定是否通过，统一以进度记录中的验收证据为准。

用户另行授权本次公开财务数据的 AI 离线试验：允许 AI 交叉核查后生成一个外部提议候选，并与冻结历史基线比较；无需将 AI 核查填写成人工复核。该试验仅用开发材料生成，验证材料用于观察迁移，保留集不参与。它复用现有未批准候选制品和隔离回放，不签发 E07、发布或激活授权，不修改正式 gold 的人工状态或签名门禁。历史基线与候选的配对诊断必须明示并非预先交替随机运行；AI 诊断指标不得冒充正式四维 rubric 或发布验收。实际登记、用量和结果仍通过进度记录链接到原始制品。

用户随后授权在当前 Max/模板基线上继续测试自进化策略。新的 AI 诊断按[独立冻结计划](../../evals/evolution/common-fundamentals-2025-v1/max-experiment-20261001/plan.md)执行：先检验开发基线，只有明确方法缺陷才生成至多一个候选，比较期间固定模型与系统模板。既有验证题仅作迁移复测；不继承历史候选资格，也不将生成器调用或 AI 评分视为 E07、人工验收或发布批准。

原版、搜索前冻结的人工固定清单和自动候选构成对照。若只运行原版与候选，只能报告该方法包差异，不能声称自动进化优于人工规则维护。保留集完成最终验收后标为已使用；下一轮候选不能只更换 experiment ID 后重复将它当作新独立验收。

V2 比较绑定 E07 策略及独立用量审计，交替执行两组，分别计算分析稿与最终回答的分组指标。验证集通过后只冻结一个候选，保留集在执行前登记源/报告家族/泄漏组的持久使用记录。最终回答未达到预先声明的效果与非退化条件、用量不完整或保留集已被另一计划使用，均不得产生发布资格。合格的签名 release evidence 仍处于 `PENDING_HUMAN_APPROVAL`，独立于发布者批准及生产激活。

四维语义评审继续使用现有 `claim_support / numeric_period_correctness / counterevidence / unknowns`；程序只自动判断明确的结构、哈希、标注数值与引用身份。缺标签不能被默认判为正确。供应商失败、数据缺口、执行错误、方法错误、评估故障分别保留，模型自评和点赞不作为发布依据。

## 隔离、发布与回滚

回放入口只在 `evolution-eval` profile 注册，并沿用 `/api/eval/**` 的管理令牌保护。它只执行已登记用例和已登记方法，不调用实时取证、不写正式会话/报告/记忆或索引。每次响应记录独立运行事实，不继承来源答案的评分和用量。

这只描述回放调用链的边界，不能当作完整 Spring 应用的网络沙箱。真实验收使用独立实例、专用存储和供应商出口规则；其他应用后台任务、数据库计数不变及网络隔离必须另行实测。

2026-10-05 起，上线治理简化为"经验注册表状态机 + 方法包内容哈希 + 人工批准 + 后端灰度配置"：发布签名、SHADOW 回放和签名激活授权已归档（见 [evals/evolution/README.md](../../evals/evolution/README.md#approval-rollout-and-withdrawal)）。启动时加载由 sha256 固定的已批准包；`rollout=OFF|ALLOWLIST|ALL` 决定生效范围；线上选用只比较模型配置与最终回答规则两项条件，不再比较记忆、RAG 和构建哈希；控制目录的 `STABLE_ONLY` 或 `REVOKE.<bundleId>` 标记无需重启即可让新请求回到基线，已固定方法的进行中请求不受影响。

上线前仍须具备保留集上的 `IMPROVED` 效果证据和人工批准；灰度建议先用 `ALLOWLIST`。
