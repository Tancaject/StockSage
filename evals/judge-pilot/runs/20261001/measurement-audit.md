# 评测体系复核与结论修正

**首轮结果暴露了评测设计缺陷，不能把参考标签与判官的全部分歧称为已确认的判官误判。** 本次只复核已有 DEV 材料，没有调用模型、修改参考标签、修改正式评分实现或重新使用 VALIDATION。原始运行与冻结结论保留。

## 标准与标签没有完全对齐

权威标准是 [ordinary_answer_quality.py](../../../../ordinary_answer_quality.py) 的 `REVIEW_REQUIREMENTS`。校准集说明另外规定了“指标错配不归入反证”“算术错误不自动归入不确定性”等归属惯例，但这些细则没有作为统一标准传给判官。不能要求模型遵循未给出的标签习惯。

- `meta-cy2024-q4-02`：证据明确没有全年营收指引，答案却声称公布了确定区间。参考标签仅因使用“指引/预计”就让 `unknowns` 通过；权威标准明确禁止将缺失信息补成确定答案，判官判 FAIL 有直接依据。这一标签存在实质争议；来源数值核对正确不代表分维语义标签已正确。
- `nvda-fy2025-q4-01`：答案已经报告收入增长和毛利率下降，参考标签给 `counterevidence=PASS`，部分判官给 N/A。应先定义“存在相关反向信息并已处理”属于 PASS，而“没有相关反向信息”才属于 N/A；不能将尚未规定清楚的边界分歧等同于放过错误答案。
- `wmt-fy2025-02`：只回答经营现金流，未回答用户要求的投入后余量。答案不完整这一事实明确，但四维标准没有明确规定任务覆盖缺失应归入哪一项、是否跨维计错。需要显式定义任务完成检查，并划清与事实支撑、反证、不确定性的关系。

## 契约检查扩大了局部问题

`msft-fy2025-q4-01` 的四项模型判定均与参考标签一致，却因为 N/A 的反证项没有摘录而整例失效。对“不存在相关反证”机械要求两侧非空引文，并不能证明已遍历相关材料。应以完整输入绑定、明确检查范围和不适用理由为依据，不能用任意摘录替代这种说明。

此外，runner 输出的摘录错误原本标明维度，校准器却将 `review.errors` 复制给所有维度，连带丢弃其他可独立核验的判断。重新统计这些局部错误后，原版额外丢弃 27 个维度（26 个符合原标签），候选额外丢弃 3 个维度（全部符合原标签）。计数与原始制品哈希见 [measurement-audit.json](measurement-audit.json)。这只是只读诊断，不是按新规则追改旧成绩。

## 先前数字的解释需要更正

| 仍沿用旧契约的 DEV 指标 | 原版 | 候选 |
|---|---:|---:|
| 技术有效维度数 | 72/144 | 92/144 |
| 有效维度内与参考标签一致 | 58/72（80.6%） | 71/92（77.2%） |
| 全部维度内与参考标签一致 | 58/144（40.3%） | 71/144（49.3%） |

40.3% → 49.3% 同时受技术有效覆盖与语义判断影响，不能单独解释为判官准确率改善。14 → 21 也只是不同有效集合上的标签分歧数量；其中还包含上文有争议的标签。在双方共同有效的 52 个维度上，原版与候选分别有 12、16 个标签分歧，仍未显示候选改善，但这也不是已校准真值下的准确率。

技术有效、证据充分、任务完成和语义正确应分别报告。全样本指标仍需保留以反映实际可用性，不能只挑出成功输出计算高准确率；比较时同时报告共同有效样本的判断变化和覆盖增减。弃权不能被算作正确，也不能被直接算作业务答案错误。

## 修正顺序

1. 将适用性、任务完成与跨维归属规则归入一个版本化权威标准，再据此裁定争议标签。争议未解决前，不能直接将这些分歧作为候选的纠错目标。
2. 区分全局失败和局部校验失败：输入绑定、模型调用、完整 JSON 失败影响整次评审；单个维度的摘录问题只影响该维度。统计与候选准入变化使用新版本，原始结果不覆盖。
3. 简化执行：已保存的证据可由程序直接提供，确定性的检查由代码执行；确实需要额外计算时才让模型调用工具。避免“已经给出增速 → 倒推未提供基数 → 再验证原增速”这种循环验证，并给最终判断保留执行机会。
4. 先证明固定判官在校准样本与实际业务输出上可靠，再恢复候选优化；独立验证必须使用新来源组。代码测试通过不能替代标准有效性与标签正确性的证明。

本次修正收回的是对测量结果的过度解释；候选未采用、AI 诊断没有发布资格及原业务 HOLDOUT 未使用的事实不变。当前实现仍是诊断原型，不是已经校准的自动选优系统。

## 缺陷为何未被前期检查发现

标准采用了现有四维原则，标签编写又补充了更窄的归属惯例，二者没有合并为判官实际收到的一份可操作标准。来源与算术复核只能证明事实基础，不能证明语义标签符合这些原则；此前把两者等同，是审查范围的错误。

错误作用范围也没有统一约定。runner 把有维度名称的局部摘录错误写入 `errors`；calibration 把该列表当作全局失败再复制到四维。runner 测试只检查坏摘录不能整体通过，calibration 的坏摘录测试则直接修改维度内容、仍令 `errors=[]`；因此各自测试通过，真实数据交接却没有被覆盖。N/A 强制引文规则也缺少针对其语义适用性的检查。

全样本一致率的计算保留所有失败项，能反映端到端可用性并防止通过弃权提高成绩。但实现和汇报没有清楚区分这类指标、有效输出内一致性以及共同有效样本比较，导致对数字作出超出其含义的解释。统计单元测试只能证明按给定标签算对了数，不能证明标签正确或指标解释成立。
