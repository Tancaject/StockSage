# 普通答案评测 Agent 首轮校准

> 后续[测量口径与标签审计](measurement-audit.md)发现了标准/标签不一致及局部校验错误扩散。下表中的“错误判断”应理解为当时参考标签下的分歧，不能视为已确认的真实误判；全样本一致率也不能单独当作语义准确率。原始运行保留，修正解释以该审计为准。

本轮已完成实现验证及真实模型试验，**判官可靠性未通过，自动生成的候选未采用**。可运行的流程是：冻结答案/证据 → 逐维 AI 评审 → 校准 → 批量开发集错误生成一个指导词候选 → 同标准比较 → 固定版本验证。业务 Agent 的模型、模板和发布状态不受本轮影响。

数据定义见[校准集说明](../../README.md)。全部 30 个答案是依据官方材料编写的校准案例，标签由两次 AI 来源/计算核查建立；不是实际业务回答或人工金标。18 个 DEV、12 个 VALIDATION 按公司和报告分开，每例重复两次。原业务 HOLDOUT 未读取或运行。

## 测量结果

| 指标 | 原版 DEV | 候选 DEV | 原版 VALIDATION |
|---|---:|---:|---:|
| 评审尝试 | 36 | 36 | 24 |
| 格式与证据绑定有效 | 18/36 | 23/36 | 10/24 |
| 给出已知判断的覆盖率 | 44.4% | 63.9% | 41.7% |
| 四维与参考标签完全一致 | 58/144（40.3%） | 71/144（49.3%） | 36/96（37.5%） |
| 四维已知错误判断 | 14 | 21 | 4 |
| 四维误放：应 FAIL 却判通过/不适用 | 0/42 | 2/42 | 0/24 |
| 四维误杀：应通过/不适用却判 FAIL | 13/94 | 17/94 | 1/72 |
| 两次均有效且有已知标签的案例中，判断完全相同 | 6/6 | 7/10 | 3/3 |

DEV 有一个刻意缺失捕获证据的案例，重复两次，正确结果为 NO_DATA。因此“有效评审”与“已知判断覆盖率”的分子不同。四维一致率以全部应评项目为分母，无效/缺失评审不会因弃权获得正确分；真实的证据不足且正确判断为 NO_DATA 才计一致。上述误放/误杀率也须结合覆盖率读，不能把大量未判定解释成零错误。

候选恢复了部分原来无效的判断，但也新增错误与退步；配对比较未达到事先声明的条件。重复一致性的有效案例集合不同，样本数很少，不能用原版的 6/6 宣称整体稳定。

## 已定位的缺口

1. 输出契约：N/A 项漏摘录、改写摘录或添加省略号、返回 Markdown 包裹 JSON，导致评审失效。精确摘录验证发现了问题，没有将它自动修成通过。
2. 工具流程：重复读取或为来源已披露的数值进行无必要推算，部分案例在四次调用预算内未返回最终评审。生成输入保留了错误文字，但本轮未包含具体工具轨迹和调用预算，限制了候选对原因的判断。
3. 语义归因：事实错误被重复惩罚到不确定性维度，反面信息已经处理时 PASS 与 NOT_APPLICABLE 仍不稳定。生成候选也引入了与证据缺失处理冲突的规则。

下一轮应先修正可观察到的输出与工具流程，给候选生成器提供实际失败轨迹和固定预算，并明确逐维判定边界；修改标准时必须升级标准身份并重新评双方。本次验证集已使用，不能看过结果后继续调参并称其为未见验证。需要用新来源组检验下一版的独立效果。

本轮没有自动安装候选，也未签发人审、E07 或发布资格。代码检查证明实现契约，AI 标签校准证明本批样例上的一致与分歧；二者都不能替代真实业务输出和独立人工校准。
