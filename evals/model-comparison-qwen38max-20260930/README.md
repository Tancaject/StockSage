# STANDARD 模型对照：qwen3.7-plus / qwen3.8-max

后续记录：[超时调整与 WMT 评分澄清](follow-up-timeout-wmt-clarification.md)。下表保留原匿名主判；WMT Max 的一个 `ISSUES` 是会计范围措辞的严格解释，不能当作已证实的实质错误。后续按核心作答解释为通过并附歧义说明，不是新增模型运行或模型修复后的成绩。

本次按用户要求将 [STANDARD 配置](../../stocksage-backend/src/main/resources/application.properties) 的默认模型改为 `qwen3.8-max`。配置优先级不变，环境变量仍可覆盖默认值。未重启常驻后端或部署打包产物。

## 结果

16 次真实调用全部正常结束，返回模型名均与请求一致，无自动重试。按预先固定的标准，隐藏模型标签的 AI 主判如下；“通过”表示整篇在本题标准下未发现实质问题，不只是抄对必答金额。

| 场景（每模型 2 次） | qwen3.7-plus | qwen3.8-max | 逐答案证据 |
| --- | --- | --- | --- |
| MSFT 流动性分析 | 0/2 | 2/2 | [复核](review-fundamentals-msft-fy2025-liquidity.json) |
| WMT 现金流分析 | 0/2 | 1/2 | [复核及歧义](review-fundamentals-wmt-fy2025-cashflow.json) |
| 新闻摘要解释 | 0/2 | 2/2 | [复核及歧义](review-news-snippet-missing-event-time.json) |
| MSFT 最终汇总 | 0/2 | 2/2 | [复核](review-final-msft-fy2025-liquidity.json) |
| 合计（主判） | 0/8 | 7/8 | [机器可读汇总](assessment.json) |

**评分敏感性：**新闻的两份 Plus 答案若将“已确认/能证实”完全读作摘要转述，并将业务用途完全读作一般假设，可从 0/2 变为 2/2。WMT 的两份 Max 答案涉及“未分析后续现金需求”与“当前 CFO 口径排除该项”的歧义；全部严格解读是 0/2，全部宽松解读是 2/2。因此整批通过数的解读范围为 Plus **0–2/8**、Max **6–8/8**。主判不是唯一可能评分，新闻和 WMT 的模糊措辞不作为最强改善证据。

较明确的证据来自两个 MSFT 阶段：Plus 重复出现由递延收入和静态余额直接确认真实兑付压力很小/安全的结论；最终稿还会丢失正确分析稿中的限制。Max 的四份对应回答均保留了账面覆盖与实际偿付能力的区别，没有同类确定性保证。该差异在上述宽松/严格评分下保持不变。

两模型在财务题的必答金额和主公式均正确，不能将本轮结果解释为“Max 修复了普遍算术错误”。Plus 仍有必答科目范围扩大（把 PPE 写成含无形资产）和额外增速的轻微误差；更主要的问题是会计解释及证据不足时的推断。WMT 利息口径的核查使用 [FASB SFAS 95 §23](https://storage.fasb.org/aop_fas95.pdf) 和 [WMT 完整年报](https://www.sec.gov/Archives/edgar/data/104169/000010416925000021/wmt-20250131.htm)；这些是审核依据，未加入被测模型输入，也不要求模型补答未提供的细目。

另外，两个模型各有一份最终稿把额外 FY2024 流动比率写为约 1.28，原值 1.2749549 按常规两位小数应为 1.27。两者采用相同口径记轻微舍入，不影响主判；上面的范围沿用冻结标准对轻微舍入的容忍。若另改为所有附加数字零容差，Max 会再少一份通过，但其保留实质风险边界的改善仍在。不能将“附加数值通过”解读为全部显示精度严格无误。

**结论：**在当前提示词及这些故障场景上，模型选择确实影响回答的可靠性，不能把此前问题全部归因于 RAG 或提示词。Max 在本轮有改善，但仍存在歧义表述；这不是对整体准确率、独立财报来源泛化能力或所有原值错误的证明。固定证据的设计排除了本轮两侧检索差异，不能证明完整系统的检索与入库从此没有问题。

## 耗时与用量

| 描述性指标（各 8 次） | qwen3.7-plus | qwen3.8-max |
| --- | --- | --- |
| 同步完整生成耗时中位数 | 43.4 秒 | 73.5 秒 |
| 最短–最长 | 27.1–64.0 秒 | 39.3–137.5 秒 |
| 供应商报告总 token | 37,157 | 47,081 |

Max 本轮总 token 多约 26.7%，耗时中位数约为 Plus 的 1.69 倍；这不是货币费用比较，也不是吞吐量或线上延迟基准。整个实验共 84,238 个供应商报告 token。

两次 Max 的 `outputTokens` 分别为 6,923 和 5,207，高于显式请求的 `maxTokens=4096`，但均正常 STOP。记录中没有推理 token 拆分，不能声称实际总生成 token 被限制到 4096，也不能将差异完全归因于模型规模。此实验比较的是供应商在相同显式参数下的模型选择，内部推理策略、分词及默认参数差异未被单独控制。

## 比较范围

固定当前已交付的提示词、原始证据、输入顺序、温度 `0.7`、输出上限 `4096` 及其他显式请求参数，只替换模型 ID。两侧均重新调用真实供应商；未将历史结果当作本轮旧模型结果。

四个场景各对每个模型调用两次，共 16 次：MSFT 基本面分析、WMT 现金流分析、缺少事件时间的新闻摘要、MSFT 最终汇总。每个场景第一次先调用 Plus、第二次先调用 Max。最终汇总使用同一份冻结的正确分析稿，不重新执行分析师步骤。新闻是合成摘要，其余使用既有公开财报开发材料。

这是四个刻意选取的故障场景；其中两个共用 MSFT 来源，重复生成也不是独立题目。`provenance.json` 中 `independentCases: 4` 仅表示四个场景，不代表四个统计独立样本。没有使用 validation/holdout，也不据此推断总体准确率。

## 运行边界

本轮是真实供应商的同步消息重放，没有启动完整服务、执行检索/工具/存储或重新抓取数据。运行身份是 `UNATTESTED_LOCAL_CLASSES`，不是历史固定 JAR 的验收。请求最大尝试次数为 1。

该组件重放的 HTTP 连接与读取超时均为 `UNSET`（未显式配置，不表示已证明无限等待），不应用普通在线流程的分析师等待上限。[ToolPrefetchService](../../stocksage-backend/src/main/java/com/stocksage/service/ToolPrefetchService.java) 使用配置中的阶段等待上限，默认 30 秒；[OrdinaryAnswerReplayService](../../stocksage-backend/src/main/java/com/stocksage/conversation/OrdinaryAnswerReplayService.java) 也使用该阶段限时。因此完成一次组件调用不等于在线请求能在现有限时内完成；同步完整生成耗时也不等于流式首字延迟。供应商内部模型修订、未显式指定的默认参数和实际货币费用未知。
