# 批量学习前置修复验收

本轮修复业务调用的推理预算与期限配置，以及基本面原生评测适配器的协议问题。业务方法、问题、来源、标准答案和四维评分标准保持不变；这是固定证据组件链诊断，不是进化收益或线上全链路验收。

## 业务配置与真实回放

同六题包含四道原超时题，以及 PEP 单季还原、TGT 现金质量两个原本通过的对照。每组分别登记，失败记录保留，不在原 runId 下重试。

| 思考预算 / 单阶段期限 | 获得两阶段答案 | 每阶段必答数值 | 分析稿完整语义 | 最终回答完整语义 |
|---|---:|---:|---:|---:|
| 4096 / 180 秒 | 6/6 | 38/39 | 0/6 | 0/6 |
| 8192 / 180 秒 | 6/6 | 39/39 | 1/6 | 0/6 |
| 32768 / 300 秒 | 6/6 | 39/39 | 6/6 | 6/6 |

语义判断来自独立 AI 逐项来源复核，没有读取自动评审结果。对应证据：[4096](secondary-business-review.json)、[8192](budget8192/secondary-business-review.json)、[32768](budget32768-timeout300/secondary-business-review.json)。两个历史对照也按相同规则重新检查，仍为通过，见[配对复核](paired-baseline-control-review.json)。这些比例仅描述六道诊断题，不代表系统总体正确率。

4096 的主要问题包括 IBM 的 `9115/3109` 写成 1.93、JNJ 递延税费用对利润的方向解释反了、把单季与半年累计比较称作环比，以及无来源的行业、历史和经营原因断言。8192 修正了必答数字，但完整解释仍有错误。因此没有采用这两组配置。32768 组先通过两个对照的独立复核，再执行四道原超时题；依据保存在[阶段登记](budget32768-timeout300/phase2-authorized.json)。

此前只限制回答 token，没有显式限制思考预算。官方说明这两者独立，未设置的 Max 使用 xhigh；4096 属于 low，8192 属于 medium，32768 属于 xhigh。[阿里云参数说明](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)。本轮证明了不同设置下的实际结果差异，不能把历史超时全部归因于思考长度；原超时调用没有完整响应或用量，且高预算组同时改变了期限。

默认配置已设为 `qwen3.8-max`、思考预算 32768、共享阶段期限 300 秒。同步 HTTP 读取期限引用同一阶段配置。思考参数仅注入基本面 Max 和 STANDARD Max 最终回答；共享期限还影响 MARKET/NEWS 等分析等待、可选 DEEP 补证决策及同步 HTTP 默认值，DEEP 的剩余总期限仍生效。正常聊天 SSE 没有与回放相同的整次生成期限。

[默认配置验证](production-defaults-preflight/verification.json)从新 JAR 读取实际生效值，没有模型、思考预算或期限的试验覆盖参数，并通过本地真实 HTTP 请求检查。此预检没有调用模型，也没有重启常驻服务。真实六题使用原试验 JAR 加显式配置，新 JAR 验证的是默认配置绑定，二者证据范围不同。

**仍有运行限制：**高预算组 4/6 草稿超过既有 4500 字符传递上限，原始分析完整保存，但传给最终回答的草稿被截断，任务如实标为 `TRUNCATED / DEGRADED`。六题内容通过不等于六题运行无降级。两阶段模型耗时合计约 145～446 秒，最慢约 7 分 26 秒；300 秒是单阶段期限，不是整题期限。逐题记录见[运行状态与耗时](budget32768-timeout300/execution-outcomes.json)。本轮没有通过提高截断上限或清除降级标记来改善报表。

## 原生评审适配器

适配器使用基本面专属 rubric、数值规则和来源绑定；普通回答评测 Agent 的试用结果不能转移到这里。修复包括：

- 用登记的行号还原原文引用，拒绝虚构行号与错误来源；接受完整 JSON 围栏，仍拒绝截断输出。
- 允许足够的受限计算调用，并明确金额、同比差额和变化率是不同指标；非数值原因在语义维度评价，不伪造数值记录。
- 只合并经单位、精度及既定容差验证的等价比率；错误重复保留为失败，原始抽取仍可审计。
- 明确无来源的数字主张可以在 `support=FAIL` 时留空证据引用；答案引用仍须真实，失败不会被改成通过。

原始适配器在 16 个历史有答案阶段中仅 3 个有效。第一次协议修复的新调用得到 15/16 有效；确定性处理等价比率后，缓存重放得到 16/16 有效。两个另行编写的错误负例也在缓存重放后均被判错。这里的最后一步没有新 API 调用，不能称为新模型准确率 100%，见[缓存重放记录](judge-recheck.json)。

再用 4096 业务组的 12 个真实错答验证，发现技术有效仅 9/12、正确判错仅 5/12，另有 3 个误放行、4 个无有效判定。这个失败结果没有被旧答案的通过率覆盖，见[真实错答首轮审计](judge-new-summary.json)。

后续固定回归集由这 12 个真实错答阶段和同题的 4 个旧正确阶段组成。预期判定只在评审返回后附加，不送给模型；使用高推理预算继续验证协议与语义判断。完整原始结果见[16 阶段登记](judge-v4-high-plan.json)、[逐阶段结果](judge-v4-high.json)及[独立审计](judge-v4-high-summary.json)。

v4 的完整首轮结果为 **11/16 = 68.75%** 阶段结论与独立参考一致：8 个错答正确判错、3 个正确回答保留通过；没有有效的误放行或误拒绝，但 5 个阶段无法判定，均计入分母。技术有效 12/16，其中一个是 NO_DATA，技术有效不代表判对。

其中 3 个无效结果的 provider `finish_reason=length`：评审为完整抽取约 40 个数值主张生成 JSON，超过 6000 回答 token 上限。另两个未决阶段分别为 PEP 分析稿返回非法状态 `UNKNOWN_PLACEHOLDER`，以及旧 TGT 分析稿返回 NO_DATA／占位理由。这是模型实际输出，不能由程序或独立参考标签补成正确答案。部分阶段虽结论正确，仍有维度遗漏或矛盾；阶段结论一致率不等于维度准确率。

v5 只把回答上限从 6000 调到 12000，其他设置、协议、标准与答案均未改。[定向登记](judge-v5-length-plan.json)仅包含上述三个被截断阶段；[新调用结果](judge-v5-length.json)三项均为 VALID／FAIL，与独立负例标签一致，最后一轮均正常 `stop`，完整保留 40、46、42 个数值主张。这个 3/3 证明了这三个阶段的截断修复有效，不能替代 v4 的完整首轮 11/16，也不能称为 v5 全量或新数据准确率。

两项占位结果未被重试或修改，其他维度遗漏仍保留。当前原生评审用于辅助诊断，不能独立决定学习入选或自动发布；所有评审仍为 AI_ONLY，正式发布门禁保持 NO_DATA。

## 实际用量

业务三组各调用 12 次；下表按实际供应商响应汇总，缓存重放没有新调用。token 不等于费用，业务响应也没有单独报告思考 token。

| 业务组 | 输入 token | 输出 token | 总 token |
|---|---:|---:|---:|
| 4096 / 180 秒 | 38,753 | 26,265 | 65,018 |
| 8192 / 180 秒 | 41,755 | 34,720 | 76,475 |
| 32768 / 300 秒 | 43,620 | 81,681 | 125,301 |
| 合计，36 次调用 | 124,128 | 142,666 | 266,794 |

原生评审的初次修复及两个编写负例共 37 次调用、346,276 tokens；12 个真实错答的 v3 评审共 24 次、272,921 tokens；v4 完整 16 阶段回归共 38 次、662,881 tokens；v5 三项定向复测共 7 次、124,997 tokens。本轮业务与评审合计 **142 次调用、1,673,869 tokens**，不含此前原始批量学习调用；每次响应均有供应商总用量，各轮失败也保留在合计内。没有配置账单价格，因此不报告推算费用。机器可读汇总与证据 SHA 见 [result.json](result.json)。

## 冻结记录与验证边界

原首轮结果保持原样，修复前 59 个冻结输入及计划保存在[原始输入快照](../batch-learning-20261002/frozen-inputs.zip)。本轮早期三个业务计划及真实错答评审所用的 44 个冻结文件（含计划）保存在 [v3 输入快照](frozen-v3-inputs.zip)，逐项按原计划 SHA 验证。历史计划指向的部分工作区源码已更新，重现历史身份应使用快照，不能用当前代码伪装原版本。
