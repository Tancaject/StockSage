题目覆盖微软、沃尔玛的增长质量、现金流覆盖和期末流动性。它们是同一既有开发集，题目之间共享发行人及报告家族；6/6 不是整个系统准确率，也不是模型已经不会出错。AI 核查未冒充人工标签。评审标准在供应商调用前冻结，见 [criteria.json](criteria.json)；逐条引文、计算与分歧见 [微软核查](review-baseline-msft.json) 和 [沃尔玛核查](review-baseline-wmt.json)。

沃尔玛现金流最终稿正确计算了 CFO、毛额资本开支、简化 FCF 和占比，但把“不考虑折旧摊销”等项目统称为“其他现金项目”。字面上可能把非现金调整误称为现金项目；结合全文也可以理解为差额公式没有再单独调整这些项目。按冻结的完整语境规则，主判记歧义，保留严格评审的分类问题及裁决过程。不能将此扩大成算错 FCF 或不理解 CFO。它也不是分析稿中的同样错误，不能直接判作分析方法失效。

## 实际运行

复用了现有固定 JAR 两阶段组件回放，不改生产代码。新进程从应用配置实际绑定 `qwen3.8-max`、temperature 0.7、请求 maxTokens 4096、阶段等待 180 秒；HTTP 读取在启动参数中设为 180 秒，无自动重试。两阶段返回的实际模型均为 Max，方法仍是 `baseline-v1`。运行参数、原始输入/回答和用量分别见 [分片 1](raw-baseline-1/runtime.json)、[分片 2](raw-baseline-2/runtime.json) 及同目录 `responses.jsonl`。

[执行审计](baseline-execution-audit.json) 通过：6 个登记 run、12 次模型调用均完整，每次一份供应商用量快照，实际模型与固定构建身份一致。总用量 **93,648 tokens**，未定价，不等同账单。没有生成器、迁移复测或 HOLDOUT 调用。

- 分析阶段中位数 **129.95 秒**，最大 **158.55 秒**。
- 最终阶段中位数 **62.64 秒**，最大 **70.65 秒**。
- 每题两阶段耗时之和中位数 **192.97 秒**，最大 **227.54 秒**；这不是在线首字延迟或 HTTP 端到端耗时。
- 4 次分析的供应商 `outputTokens` 高于请求的 4096。原始值照实保留；推理/可见文本拆分及 `finish_reason` 未记录，不能仅凭该现象认定截断或把请求值当实际总量硬上限。

[build.json](build.json) 绑定本次源码快照和新 JAR。驱动及外部依赖另记于 [driver-dependencies.json](driver-dependencies.json)，启动参数为 [baseline-1.args](baseline-1.args) 和 [baseline-2.args](baseline-2.args)。实际 JAR 保留于 `stocksage-backend/target/evolution-build-max-20261001/`；打包器排除了本地 profile 和环境文件。运行前 fast harness 通过：后端 772 项、1 项跳过，前端测试/构建及 Python 编译通过。

## 对策略的判断与优化点

1. **先确认方法缺陷，再生成候选。** 本轮没有足够的正向触发材料。预算是上限，不是必须完成的调用数；无需为了产生“进化结果”扩大歧义扣分或改写本来正确的方法。这里是 AI 诊断后作出的停止决定，不是已经证明在线系统会自动触发或自动拒绝进化。
2. **按阶段归因。** 分析稿正确、最终稿新增的问题应进入最终整合的诊断。仅允许修改分析方法的 V1，不一定能修复另一阶段的扩写；有真实问题后才值得测试方法能否间接改善它，不能先承诺有效。
3. **下一轮质量数据需要来自正常任务中的明确失败。** 本轮固定原值三类题出现了评分上限，无法显示候选收益。可以从日常季度/年度比较、多份财报合并和科目口径转换任务中收集来源可复核的失败，再按发行人和报告家族分组；不是增加不太可能出现的极端题。后续新样本尚未建立或调用。
4. **延迟与重复展开值得单独比较。** 分析稿与最终稿都反复展开完整表格和计算，当前每题两阶段约需数分钟。缩短中间稿、减少重复呈现是待验证假设；需固定同样任务覆盖和正确性进行对照，本轮没有改模板，也没有测得该优化收益。
5. **补足完成状态观测再解释输出预算。** 当前缺失 `finish_reason` 及供应商推理/正文用量拆分，妨碍判断 4096 之外的输出构成。应先记录可获取的原始字段，再决定是否调整预算，不能编造供应商行为。此项仅登记为后续工作，未在本轮修改运行器。

本轮是固定证据的真实模型组件试验；没有调用实时 RAG、启动完整业务服务或重启驻留后端，因此不证明检索、入库、HTTP 链路或部署质量。无候选发布或激活，正式 E07、人工独立验收和全计划状态仍以 [progress.md](../../../../progress.md) 为准。原 VALIDATION 已暴露，HOLDOUT 元数据接触情况及保护边界见事前计划；本轮没有使用其答案或进行留出推理。
