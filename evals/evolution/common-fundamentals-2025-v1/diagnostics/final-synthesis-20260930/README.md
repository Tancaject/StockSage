# 最终汇总故障定位：提示规则有贡献，数值与证据核验仍不足

固定正确分析稿、可见报表、模型与参数，只调整最终系统提示中五条“强制表态”规则，完成 12 次真实最终生成。结果支持这组规则会推动部分无依据的经营解释；同一干预没有解决所有科目、数值和事实约束问题。本诊断不修改生产提示词、不生成新的基本面方法候选，也不授权发布。

## 对照结果

指标为“必答内容完整，整篇未发现实质性数值或证据问题”的 AI 来源核查通过数，不是正式发布 rubric。

| 冻结案例 | 原规则 | 证据范围内表态规则 |
|---|---:|---:|
| WMT FY2025 现金流 | 0/3 | 3/3 |
| MSFT FY2025 流动性 | 1/3 | 1/3 |
| 合计 | **1/6** | **4/6** |

两组必答金额与计算均为 6/6 正确；额外数值均为 5/6 正确。干预组保留全部任务覆盖，改善没有依赖拒答或删除必答内容。逐答案原句、判定、映射、分项统计及用量以 [diagnostic-assessment.json](diagnostic-assessment.json) 为准。

**WMT 的区别可重复观察到。** 原规则三次都将报表总额扩展为缺少披露支持的具体投资投向、管理层意图或融资/回报覆盖判断。调整规则后三次都保留 CFO 覆盖指定 CapEx 的结论，同时保留具体投向未知和口径限制。证据、分析稿和模型未变，因此支持这组系统规则对该案例的错误具有因果贡献。

**MSFT 尚未整体改善。** 原规则仍出现递延收入剔除后的安全保证、未披露业务原因，以及把现金增长约 65.1% 写成翻倍。调整规则后的三次回答都保留了流动性限制，但其中一份把“其他非流动负债”写成 91,444 百万美元，遗漏长期未确认收入 2,710，正确合计为 94,154；另一份在没有现金流表的情况下仍预设“强劲的经营现金流”。不能因此宣布汇总问题已解决。

## 如何隔离变量

执行前冻结 [plan.json](plan.json) 与 [diagnosis.json](diagnosis.json)：两道 DEVELOPMENT 题，每题两组各三次。原样组使用过去已保存的实际最终 messages，但重新调用模型，不以历史失败答案充当本轮对照。干预只改变首条 system 消息中的五条规则，其余消息逐字一致，不加入公司、金额或本题专属纠错提示。

五条改动将必须评价财报强弱、必须解释同行/历史位置、信息不足仍不回避表态等要求，改为仅在提供相应依据时判断，缺少证据时保留未知。它检验的是一个规则组，不能把效果归因到其中某一句；首条系统消息长度也从 1,257 变成 1,188 字符。

固定输入分别来自候选的 MSFT 流动性分析和基线的 WMT 现金流分析，两份原分析稿在此前 AI 核查中通过。分析稿全文均在最终输入中，所需财务原值和限制也可见。源文件尾部的空白、页码或 accompanying-notes 提示并非逐字全部进入历史输入，因此不声称完整源文件字节都被传入。两组在本实验中使用相同可见文本。

模型实际为 `qwen3.7-plus`，温度 0.7、输出上限 4096、单次超时 120 秒、无自动重试。沿用冻结生产 JAR 和真实 `OrdinaryAnswerReplayService → Coordinator` 链路；只扩展外部测试驱动的 final-only 入口。未调用分析模型、在线检索、入库或数据服务。

顺序由登记随机种子产生，按题目与重复编号成对执行，组内顺序随机。实际排出的顺序是 WMT 三对在前、MSFT 三对在后；MSFT 三对恰好都是原样先行。不能描述为严格平衡顺序或完全跨题交错。

## 数值错误的独立定位

[数值追踪审计](numeric-trace-audit.json) 复算了此前三处开发集错误，没有新增模型调用：

| 错误 | 原值复算 | 发生与传播 |
|---|---|---|
| MSFT FY2024 营业利润率变化写成 +1.85 个百分点 | `(109433/245122 − 88523/211915) × 100 ≈ 2.8714` | 原值已在分析输入；分析稿生成错误，最终稿照搬。 |
| WMT 两年 CapEx 增长写成 41.4% | `(23783/16857 − 1) × 100 ≈ 41.0868%` | 原值已在分析输入；分析稿生成错误，最终稿照搬。 |
| WMT 租赁义务合计写成 15,122 百万美元 | `1499 + 800 + 12825 + 5923 = 21047` | 四项都可见；分析稿合计错误，最终稿未重复此数。 |

这些实例排除了“所需原值没取得或没传入”的解释。仅凭错误输出无法还原模型内部计算；例如去掉 5,923 后仍是 15,124，而非 15,122，不能断言它一定按某种具体路径漏项。

## 根因判断及尚未验证的部分

1. **最终生成的任务要求存在可验证的影响。** 强制总体表态规则组在 WMT 对照中扩大了无依据解释；规则调整在同模型下减少了这些错误。
2. **模型生成的科目、数字和新增断言仍缺少有效核验。** 原值可见仍会算错，最终汇总也会照搬或新增错误；提示规则调整没有改善本批额外数值的整体通过数。
3. **此前方法进化覆盖不到完整故障链。** V1 候选仅改 `fundamentals.method`，没有改变本次被干预的最终规则；“要求自查”的方法文字也没有将算术变成程序计算。因此不能用分析方法一次优化承担全部修复。
4. **本次未检验 RAG 和模型替换。** 不能将错误归因于本次未运行的检索/入库，也不能宣布线上 RAG 正常。没有同题换模型对照，不能断言已达到模型能力上限或某个其他模型一定能解决。

由证据支持的后续修复方向是：让判断强度服从可见证据，将新增数值与科目合计绑定到明确原值和程序计算，并保留最终阶段的事实与限制一致性检查。该方向尚未在生产实现或验收；本报告仅交付故障定位。

## 判定边界与复现证据

[WMT 原始核查](review-wmt.json) 和 [MSFT 原始核查](review-msft.json) 均保留。核查者读取不带组别的答案及来源，没有读取映射，但已有任务背景，不构成正式独立盲评。

MSFT 一份原样回答虽写“账面偿债无忧”，全篇明确限制为账面覆盖并保留真实兑付条件，因此按允许有限判断记为 PASS。另一份干预回答的“强劲现金流”是无证据预设，但若将该形容词视为非实质问题，干预组可记为 5/6。另作有利于对照组的宽松检查，把 WMT 一份业务意图解释判为通过，则原样组为 2/6、干预组仍为 4/6。原始评审不随这些敏感性情景改写。

只有两个为诊断选取的案例，每组每题三次；本结果不证明总体改善或统计显著性，不作为发布验收。六道保留题及验证题未被用于本次运行。
