# 单候选 AI 离线试验：未显示改善

本轮完成了一个 AI 提议候选的编译、12 题真实模型回放和两组回答的逐题核查。**候选没有改善最终回答质量，且用量与耗时增加，本轮不采用该候选。** 这是一轮有真实调用和原始回答的离线诊断，尚不构成完整自进化计划的正式验收。

## 结果

下表统计“整篇核查未发现实质问题”的回答数。两种方法、两个阶段的**必答金额和必答计算均为各 12/12 正确**；未通过的问题集中在自行补充的数值、科目、经营原因和偿债结论。

| 题目范围 | 基线分析稿 | 候选分析稿 | 基线最终回答 | 候选最终回答 |
|---|---:|---:|---:|---:|
| 开发集：MSFT、WMT | 2/6 | 1/6 | 1/6 | 0/6 |
| 验证集：GOOGL、COST | 1/6 | 0/6 | 0/6 | 0/6 |
| 合计 | **3/12** | **1/12** | **1/12** | **0/12** |

机器可读结果、逐题原句、分组统计和用量以 [diagnostic-assessment.json](diagnostic-assessment.json) 为准。这些布尔指标是 AI 来源核查指标，不是正式四维 rubric；运行报告中的 `PASS` 只表示执行契约通过，正式 `answer_quality` 仍为 `NO_DATA`。

一个边界判定是将研发费用增长表述为“通常反映公司在 AI 等前沿领域的战略性投入增加”。主评审认为公司具体用途缺来源；即将这一条按通过处理，候选分析稿也只是 **2/12**，基线为 **3/12**，最终回答统计不变。该宽松情景与原判定一起保存在结果中。

## 候选实际改变了什么

[唯一候选](proposal.json) 从六道开发题及其来源核查反馈中提炼方法，要求统一单位、复核额外数字与合计、区分科目、限制没有披露依据的经营归因，并在结论中保留资料缺口。生成者只获得开发材料，候选在运行前冻结，没有根据验证结果修改。

实际只替换 `fundamentals.method`。模型设置、固定最终汇总提示词、证据、历史与记忆快照、生产 JAR 均保持一致。[登记计划](plan.json) 和 [身份校验](identity-verification.json) 记录了这些绑定。基线复用同日已冻结的历史回答，本轮只新增候选的 24 次模型调用；它不是交替或随机运行的实验。

## 为什么没有通过

| 题目 | 候选中的具体问题 |
|---|---|
| MSFT 增长 | 额外写 FY2024 营业利润率提升 1.85 个百分点，复算应约为 2.87；仍有缺少分部依据的云/AI 解释。 |
| WMT 现金流 | 两年资本开支累计增长写成 41.4%，实际约为 41.09%。 |
| WMT 流动性 | 上轮万亿美元级的单位错误没再出现，但分析稿仍把租赁义务合计写成 15,122 百万美元，四项正确合计为 21,047。 |
| GOOGL 流动性 | 分析稿将资产侧的递延所得税误放入负债结构；最终稿又从余额变化确认主动融资决策。 |
| COST 增长 | 对 53 周比较基数的影响说反；较低的 FY2024 增速会掩盖而非夸大 FY2025 相对放缓，并且把表内可计算的费用率称为资料缺失。 |

最有价值的定位来自 **MSFT 流动性题的两阶段差异**：候选分析稿正确列出一年内到期长期债务 2,999 百万美元，明确递延收入履约仍可能花现金，且不作偿债保证；最终汇总却声称“短期有息债务已清零”“直接消除了短期刚性兑付压力”，并再次将递延收入当作可剔除的非现金负债。分析方法的改进没有稳定传递到最终回答。

这些现象支持后续单独研究额外数值的确定性校验、以及最终汇总对分析稿事实和限制的忠实性。本轮没有扩大允许修改的范围，也没有再生成候选。

## 核查方式

[核查口径](review-instructions.md) 对两组一致使用。两位 AI 核查者分别检查开发和验证题，每题阅读四份匿名呈现的回答，引用原句并复算具体问题。原始评审见 [开发集](review-development.json) 和 [验证集](review-validation.json)。题目明确要求不编造业务原因，开发集五条覆盖标记据此统一校准；[更正记录](review-adjudications.json) 保留原值、替代值和理由，原始评审未改写，整篇通过数不受影响。

这是共享工作区中的 AI 交叉核查。评审者可能已有会话背景，匿名呈现不保证严格盲评；没有填写人工审核身份、独立签名或发布许可。来源不足不必然意味着现实中为假，但不能作为本题已经证实的事实。只有四个公司、每题一次，分组统计不证明总体效果或统计显著性。六道保留题未参与候选生成、模型运行或本次回答评审。

## 实际用量与耗时

实际模型为 `qwen3.7-plus`，温度 0.7，输出上限 4096；单阶段评测上限与 HTTP 读取上限均为 120 秒，没有自动重试。两组原始运行分别见 [开发集](raw-development/runtime.json)、[验证集](raw-validation/runtime.json)，对应 [原始回答](raw-development/responses.jsonl) / [原始回答](raw-validation/responses.jsonl)。

| 项目 | 历史基线 | 本轮候选 |
|---|---:|---:|
| 分析稿耗时中位数 | 44.8 秒 | 58.6 秒 |
| 最终回答耗时中位数 | 43.2 秒 | 46.2 秒 |
| 分析阶段 tokens | 58,197 | 75,586 |
| 最终回答阶段 tokens | 76,460 | 78,510 |
| 合计 tokens | **134,657** | **154,096** |

每次调用恰有一份供应商累计用量快照。费用未定价，外部 AI 提议及核查的用量不在项目模型账本中，不能写成零成本。本轮运行条件下耗时和 token 用量增加，未观察到效率收益。

## 验证与交付边界

两个 Java 进程均退出 0；12 题执行、运行上下文、配对输入、实际模型设置、固定提示词、生产构建和 24 份用量快照校验通过。生产 JAR 沿用 [冻结基线构建](../results/20260930-packaged-qwen37-baseline/build.json)，没有重建；新外部测试驱动的源码、class 和依赖另存 [哈希记录](driver-dependencies.json)。候选注册边界的现有测试 1/1 通过，零模型预检通过，评测 registry 保持 `baseline-v1`。

`candidate.json` 是生成时的不可变提议记录，正式治理状态仍为未批准；本轮实际运行和诊断以独立结果文件记录。未执行 E07 正式接受、保留集选择、发布或激活，也未启动完整 HTTP 业务应用或验证真实存储/权限隔离。
