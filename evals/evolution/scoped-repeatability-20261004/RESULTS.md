## 修正了什么

源代码与实际匹配函数检查发现以下问题，证据见 [运行时条件核查](runtime-scope-audit.json)：

- 原始第一条经验把 `false-missing-data-claim` 放进回答前触发条件。这是回答后才可确认的错误标签，不能可靠用于回答前选择。
- 原始第二条经验的边界文字是“单位换算或百分比舍入”，而现有匹配器要求所有标签同时满足，语义不一致。
- 当前 Java 运行时不产生这两条经验所要求的详细任务/证据标签。即使给匹配函数当前全部可用标签，两条原经验仍均不匹配。
- 原有诊断组合只是把条件打印进提示词，没有执行条件选择。这不能证明线上能够按条件触发。基本面 Agent 也没有计算工具；`arithmetic` 是声明的推理能力标签，不是确定性算术已经执行的证据。

新增 [evolution_applicability.py](../../evolution_applicability.py)：对照调用方登记的可观测条件检查经验；未知条件报错，已知但不满足的条件不选入；保留匹配成员顺序。它调用现有 `experience_matches`，没有增加生产激活权限。

[适用条件修订](scope-revision.json)明确标记为**工程师修正元数据**，两条已学习经验的操作正文逐字保持不变；旧记录保持原样，新版本保留父记录哈希。第一条去掉回答后错误标签；第二条收窄到本题实际需要的 billion 换算，舍入仍只是该任务内部步骤。没有把这次人工修改冒充新的自主学习成果。

[条件观察](observations.json)在调用前由问题和来源核对并冻结：TGT 单季重建只选第一条，IBM 一次性项比较只选第二条。IBM 单季题和 TGT 流动性题均不选经验，分析消息与原基线完全一致。这两项属于静态不干扰检查，**没有记成新的模型通过样本**。该模块可选取多条同时适用的经验，不是把批量学习改成一次只能存一条。

## 执行与成本

十六个阶段全部 HTTP 200、`stop` 且收到 DONE，无断流、超时或截断；每份分析完整后才整合最终答案。观察截止仍为 600 秒，其中两份分析超过历史实验 300 秒阈值（约 307 秒和 332 秒）。这不是常驻服务当前配置或稳定性验收。

本轮 **16 次业务调用、0 次生成调用、0 次重试，总计 167,880 tokens**，全部有供应商用量。未计 Codex 复核用量，未推算账单。耗时为两阶段调用时长之和，不含调度开销；每题只有两次、推理波动明显，不能据均值宣称稳定提速。

请求保持 qwen3.8-max、temperature 0.7、max_tokens 4096、thinking_budget 32768。只有分析方法按已登记范围变化，最终消息仅替换完整分析稿。直接供应商回放不等于当前 Java 装配器或在线 RAG 验收。

## 验证与剩余工作

- 两个聚焦适用性的回归测试通过：按条件选择、成员顺序、缺前提不选入、不可观测标签拒绝和未知输入拒绝。首次测试发现命令误收集了导入的 fixture TestCase，并出现两个沙箱临时文件权限错误；改为模块引用后，只运行目标两项并通过，没有修改旧测试来掩盖失败。
- [审计脚本](audit_results.py)核对冻结输入、新经验选择、两个无关对照、全部实际请求、完整草稿替换、UTF-16 预算、十六份复核的标准/来源/答案绑定与数值、技术状态、用量及固定分母。临时阻止自动睡眠的状态均已恢复。
- 沿用本会话已记录的 fast harness 限制，未声称完整工程基线通过；见[前轮验证边界](../unit-generalization-network-20261004/RESULTS.md#验证与边界)。本轮不修改生产代码、不重启服务、不推送 Git。
- 十二道新公司迁移题未使用；正式独立验收未完成。

当前可交付的是**离线可执行的经验筛选与可重复的比较记录**。线上仍缺详细条件的可信提取器，本轮的观察是预先核查的 DEV 标注，不能拿它替代线上能力；新元数据也不会因本次 AI 复核获得发布资格。条件缺口不是上一轮离线“没有净收益”的已证实因果解释——上一轮模型实际仍收到了经验正文。

下一步应先把可观测条件目录接入生成输入和真实任务/证据来源，避免再生成运行时无法判定的标签；真实错误进入批量学习时，要先核实重复性与错误类型，再决定改经验、计算执行或最终整合。当前两道题缺少稳定失败，不继续通过重复调用或堆规则制造正向结果。生产计算器接入仍是独立待办，不能将评测端的 Decimal 工具算成业务端已经实现。
