# 业务 Agent 学习输入与经验范围修订

收窄经验在原错题上产生了可观察的收益：保留正确答案和缺失项边界，去掉全表计算，正文减少约 34%，本次耗时减少约 40%。三题小样本仍有表达错误与超时预算问题，**没有选用候选，也没有证明稳定的完整业务链收益**。

机器统计以 [result.json](result.json) 为准；事前标准和调用预算见 [plan.json](plan.json)，答案来源复核见 [source-review.json](source-review.json)。所有结果属于 AI 离线诊断，不是人工验收。

## 本轮交付

1. [学习输入组装](../../evolution_learning_input.py)只向生成器提供原方法、问题、完整分析稿、分析证据和已核查反馈，排除重复 Prompt 与最终阶段 Trace。原审计文件仍保留，并校验原来的 Trace/反馈绑定。[输入核查](input-verification.json)显示两组输入字符分别减少 **74.83% / 79.34%**；第一组的新输入还包含旧经验及工程复核指出的副作用。
2. 生成协议要求只处理用户所问或准备声称缺失的项目，不将局部纠错扩大为全表计算。第一组由模型生成[第二版经验](group-1/experience.json)，通过版本及父记录绑定保留第一版来源。修订反馈由工程复核提供，不能称为完全自主发现并修复问题。
3. 两个已确认错误组并行生成，仍是一批多组学习。第二组没有有效经验，所以本轮只隔离比较第一组；这不是把批量学习改为“一次只能学一条”。

新逻辑用于[本轮离线运行器](run.py)，未更改在线业务默认 Prompt、激活注册或驻留服务。历史实验脚本及冻结制品未覆盖。

## 生成结果

见 [生成汇总](generation-summary.json)。两个调用都由供应商返回 `qwen3.8-max`、`finish_reason=stop`，没有重试。

| 错误机制 | 结果 | 解释 |
|---|---|---|
| 可还原分项被误称缺失 | 生成有效第二版经验 | 只核查相关项目，不要求遍历或展示整张表 |
| 单位换算与派生数字不一致 | 未产生有效经验 | 返回完整 JSON，但把原题具体金额写入通用方法，被既有校验拒绝 |

第二组的[离线复验](group-2/validation-diagnostic.json)确认是内容范围违规，不是本轮 JSON 截断。没有人工删除数字后冒充模型成功。两组均返回完整 JSON 只是一轮观察，不能证明输入精简已经解决生成稳定性。

## 固定条件与标准

- 保留原十题开发集和十二题新公司迁移集。本轮按事前规则选取开发题 05（原错题）、09（已有过度计算观察）、06（原预选的不适用经验对照）；迁移题没有调用或进入生成输入。
- 共六次真实业务分析调用，比较旧经验与修订经验。每题相邻两臂执行，臂顺序交替，最多三题并行，无自动重试。模型请求固定为 `qwen3.8-max`、temperature `0.7`、正文上限 `4096`、thinking budget `32768`。
- [成对输入核查](pair-input-audit.json)确认每对输入仅一个 system 方法消息不同，用户问题与证据相同。修订包含条件标签与操作文字变化，不能把效果严格归于某一个句子。
- 两臂统一使用原始消息的直接供应商流式回放，登记观察期限为 `600s`。另行记录是否在**原实验的 `300s` 预算**内完成。该 `300s` 是历史对照预算，不是本轮确认的当前驻留服务配置；登记字段 `productionDeadlineSeconds` 应按这个限定理解。
- 复用[基本面分析四维标准](../../evolution_rubric.py)、原 gold 和[来源核查规则](../batch-learning-validation-20261002/review-policy.json)，使用现有 Decimal 派生计算核对[十五项 gold 公式](gold-calculation-verification.json)。必答数值之外，额外主张也参与判定。失败与截断留在固定分母，不当作语义答错或通过。
- [复核序列化脚本](review_results.py)保存已阅读答案后的 AI 来源判断及数值核算。它不是自动语义裁判；本轮也没有测量或借用 Ordinary 评测 Agent 的准确率。复核为非盲 AI 核查。

## 三题配对结果

| 题目 | 旧经验 | 修订经验 | 本轮观察 |
|---|---|---|---|
| 05 TGT 单季还原 | 247.562s；4,176 字符；完整 | 148.860s；2,758 字符；完整 | 两者都未重复原缺失项错误；修订版去掉整表与额外同比计算，必答金额正确 |
| 09 PEP 单季比较 | 600s 超时；仅有部分正文 | 331.844s；4,541 字符；完整 | 修订版必答金额和现金方向正确，但仍超出原 300s 预算，并有局部措辞矛盾 |
| 06 TGT 流动性对照 | 225.984s；3,191 字符；完整 | 200.031s；4,723 字符；完整 | 两份均通过来源复核；修订版正文反而更长，没有普遍缩短输出的证据 |

旧经验 09 的首个正文约在 **537.937s** 才到达，随后在登记期限中止；其部分正文不参加完整答案通过判定。

| 固定分母：各 3 题 | 旧经验 | 修订经验 |
|---|---:|---:|
| 完整输出 | 2/3 | 3/3 |
| 在原 300s 内完整输出 | 2/3 | 2/3 |
| 必答金额通过且答案完整 | 2/3 | 3/3 |
| 整份回答四维通过 / 失败 / 不可评 | 1 / 1 / 1 | 2 / 1 / 0 |

严格判定的两个失败需要区别理解：

- **旧经验 05**：必答金额正确；额外写出的 `978 / 1127 = 86.79%` 应为约 `86.7791%`，误差约 `0.0109` 个百分点，略超冻结的 `0.01` 容差。这是小数偏差，不是原错题核心计算失败。06 旧答案另有一个显示舍入差异仍在容差内，没有随意加判失败。
- **修订经验 09**：核心结论明确为现金创造同比减弱，六项必答金额正确；但额外句子“自由现金流的同比改善”与 `3480 < 3756` 矛盾。上下文应表达资本支出下降缓冲了自由现金流降幅。按额外主张也需受支持的冻结规则记录 `claim_support=FAIL`，不把它描述为核心答案全部错误。

这组三题的通过数不能代表系统准确率；样本经过开发用途选择、每臂仅一次，也未覆盖最终回答整合。耗时受抽样、并发与供应商负载影响。不能从单次耗时下降承诺固定加速比例。

## 验证、用量与边界

- 输入保真、成对方法隔离、原冻结文件哈希及 gold 公式核查通过；经验组合的既有四项测试通过。最终绑定核查见 [verification.json](verification.json)。
- `init.ps1 -Mode fast` 后端未通过：775 项，1 失败、0 错误、1 跳过。`StandardThinkingBudgetHttpTest` 预期 `300s`，测试上下文实际读到 `180s`。前端 103 项测试与构建通过，data-service 编译检查通过。基线日志在 `target/verification-learning-revision-baseline-20261003.log`。该既有配置/测试不一致未在本任务中修改；不能把本轮说成全仓验证通过。
- 两次生成、六次业务调用；供应商已报告 **71,172 tokens**，另有一次超时调用用量未知，不能按零计算。未计入 Codex 来源复核用量。
- 业务回放保存请求模型及参数；复用的探针没有独立保存响应内的 model 字段。生成调用则同时保存并检查实际返回模型。该记录边界不应被写成生产实际模型绑定验收。
- 没有启动最终整合、全开发集或迁移评测，没有候选选用、上线、服务重启、Git 提交或推送。此前分析结束原因丢失的问题按用户决定留待后续处理。

## 下一步

保留这份修订作为开发候选。优先把第二类经验的数值示例改为不含原题金额的通用单位规则，在新登记轮次重新验证；不要放松现有内容校验。第一类还需完整双阶段及剩余对照验证，才能进入新公司迁移。若最终进入在线匹配，还须验证生成的条件标签能由实际任务/证据提供；例如本轮新增的 `false-missing-data-claim` 尚没有在线匹配证据。

本轮证明了一个具体优化方向值得继续验证：**经验应修补局部错误，而不扩大整个任务。** 尚未证明自进化总体完成或稳定提高最终答案质量。
