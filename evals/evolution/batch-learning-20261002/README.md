# 业务 Agent 批量经验学习

研究问题：从一批常见财报任务中提炼的条件经验，能否改善新公司的最终回答？本轮使用固定证据的真实两阶段组件回放；结果不代表在线检索、经验选择或正式发布已验证。

实际执行、逐题结论和未完成的验证见 [RESULTS.md](RESULTS.md)。以下是调用前的实验设计，不代表每个后续阶段都已触发。

## 事前设计

- 学习／开发：IBM、JNJ、PEP、TGT，各 3 题；迁移：CSCO、ORCL、KO、LOW，各 3 题。公司及报告家族不跨组，不使用旧实验的 HOLDOUT。
- 三类需求：累计报表还原单季；同期间利润与经营现金流对照；期末债务和流动性。保留原表已给单季、期末余额等正常对照，不把差分规则套在余额上。
- 在调用前冻结问题、来源、必答项、确定性公式、评分标准及程序身份。原始材料与 AI 核查记录保留；标准答案仍为 `UNREVIEWED / AI_SOURCE_CHECKED`，不冒充人工验收。
- 业务两阶段模型固定为 `qwen3.8-max`，基础模板、工具权限、模型参数、构建及证据相同，仅改变方法经验。评审复用 [基本面阶段标准](../../evolution_rubric.py)，两阶段单独评分；普通回答评测 Agent 的校准比例不转移到本轮。

## 学习与比较

1. 批量运行 12 道开发基线，根据原始来源和逐字输出核实失败，区分分析方法、最终整合、缺数据和执行故障。
2. 仅对核实的方法错误按机制分组，最多生成 3 条条件经验；每条分别绑定来源与版本。没有错误的组保持原方法，不为凑数生成。
3. 每个候选选 4 道预先登记的开发题：相关题和不适用／基础对照各 2 道。共同基线只在构建、模型和输入相同时共享。候选须修复至少一个已确认问题且无新增实质错误，才进入组合。
4. 将入选经验编译为有序、固定身份的组合诊断包；完整方法仍遵守 2000 UTF-16 字符上限。成员条件、限制和来源身份不能丢失。
5. 冻结组合后，在 12 道新公司题上相邻运行两臂、跨题轮换顺序。主要终点是最终答案完成全部必答项且无实质错误的任务数，同时报告不可判定、执行失败、修复、新增错误、分析阶段及成本。
6. 只有新任务净改善且无关键数值／事实回退，才记为本轮支持组合收益。打平或无法判定保留基线。组合收益不证明单个成员独立有效，也不证明优于通用提示词维护。

最多 96 次业务模型调用（开发基线 24、3 个候选筛选 24、迁移对照 48），经验生成最多 3 次；每阶段评审最多 4 次模型调用，开发复核和来源核查另列。并发最多 3 个业务回放。未知调用不自动重试，失败尝试保留在分母内；若没有合格候选，停止于有证据的“不生成／不采用”，不消耗迁移组。

正式 registry 审签、发布、在线激活和评测器自优化均不在本次诊断执行内。运行和结果以本目录冻结计划、原始输出及最终报告为准。

## 运行入口

`experiment.py` 复用固定 JAR 和现有 Java 组件驱动，提供 `prepare-runtime`、`register`、`run`、`collect`、`learn`；所有输出拒绝覆盖。`register` 校验冻结输入指纹，执行清单不含 gold。`run --preflight` 只验证输入与实际运行配置，不调用模型。`learn` 批量读取已确认的方法错误组，生成独立经验和单候选，不将迁移任务送入生成器。
