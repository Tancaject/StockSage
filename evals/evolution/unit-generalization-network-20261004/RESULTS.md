# 单位经验泛化与双阶段组合验证

本轮真实模型对照已完成，**没有观察到净质量收益，不选用组合候选**。两条经验可以生成、组合并进入业务分析，但这不等于已经带来可靠的自进化效果。机器统计见 [result.json](result.json)，逐项来源复核见 [reviews](reviews/)，执行与证据绑定审计见 [audit.json](audit.json)。

## 范围与标准

[预登记计划](plan.json)固定了四道开发题、两组顺序、一次生成与最多十六次业务调用，无自动重试。基线使用原方法；组合组使用原方法加两条经验：收窄后的缺失数据核查，以及本轮生成的通用单位换算/舍入方法。后一条已通过内容范围检查，不再夹带原题金额；仍有适用条件需要后续验证，见 [scope-review.json](scope-review.json)。

质量沿用已冻结的基本面四维标准、标准答案和来源规则，分别检查分析与最终回答。复核由 Codex 对照原始来源进行，保留原文、公式和哈希，**不是已校准评测 Agent 的自动评分，也不是人工标签或准确率测量**。[复核记录生成器](review_helpers.py)只保存语义判断并检查引文/算术，不自动作出语义裁决。涉及证据充分性的定性判断仍有解释空间，具体失败原文见下文。

本轮直接向 DashScope 回放已保存的业务消息：分析阶段只替换方法，最终阶段只替换完整的新分析稿。问题、证据、其他系统约束与模型参数保持一致。实际请求为 qwen3.8-max，temperature=0.7，max_tokens=4096，thinking_budget=32768，启用 thinking/stream；不是当前 Java 装配器或在线 RAG 的全栈验收。

## 逐题结果

“通过”要求四维和题目必答项通过；额外输出的错误也计入。下表分析与最终阶段结果相同，最终回答没有纠正上游出现的两处问题。

| 开发题 | 基线分析 / 最终 | 组合分析 / 最终 | 观察 |
|---|---|---|---|
| IBM 一次性项目可比性（07） | 通过 / 通过 | 通过 / 通过 | 两边单位换算正确，历史单位错误未复现 |
| TGT 单季现金流重建（05） | 失败 / 失败 | 通过 / 通过 | 组合未出现基线的额外期间比较错误 |
| IBM 单季对照（01） | 通过 / 通过 | 通过 / 通过 | 两边均正确 |
| TGT 流动性对照（06） | 通过 / 通过 | 失败 / 失败 | 组合新增缺少证据限定的融资依赖判断 |

两组分析和最终回答各为 **3/4（75%）**；最终配对结果为一题改善、一题退化、两题不变。这只是四道开发题的一次抽样结果，不能作为总体正确率或统计显著的效果结论。所有回答的题目核心数字都通过；失败出现在额外比较或解释中。

### TGT 单季题：额外期间比较错误

基线最终回答说：“现有证据不足以判断本季资本支出较上半年增加的具体经营原因。”但单季资本支出为 978 百万美元，上半年累计为 1,864 百万美元；未转换为可比期间，不能先断言本季增加。后半句承认原因未知，并没有消除前半句的错误前提。归入 numeric_period_correctness，不重复处罚其他维度。证据见 [基线最终复核](reviews/05-baseline-finalAnswer.json)。

组合没有该错误；两边都答对了 1,127、978、149 等核心数字。旧的“可推导项目被说成缺失”在本轮基线并未复现，所以不能将这道题的变化直接归因为第一条经验修好了原缺陷。

### TGT 流动性题：新增判断超出静态证据

组合最终回答说：“公司短期流动性仍较依赖经营现金流入、应付账款周转和外部融资能力，而不是仅靠账面现金与流动资产覆盖。”当前来源只提供静态资产负债表，没有现金流、周转或融资安排，不能确认该公司具体依赖关系。说明一般的未来现金流需求可以成立；这里的问题是将其表述为该公司已确认的状态。归入 claim_support，见 [组合最终复核](reviews/06-combined-finalAnswer.json)。

同题基线明确将外部融资、经营现金流支持能力留待验证。其短债覆盖判断限于静态数据；核心金额、正反信号和数据缺口均正确。该项失败属于推断范围和限定语问题，不是虚构融资交易或核心计算错误。若后续独立裁决不同，应保留本次判断及裁决记录，不改写原结果。

### IBM 单位题：没有证明单条经验收益

两组均正确把 0.3/0.7 billion 换算为 300/700 百万美元，调整后净利润为 5,293/5,134。组合显式写出换算过程，但基线也答对，不能据此宣称经验带来改善。4.61 个百分点的表述与未舍入结果相差约 0.00537，仍在冻结的 0.01 容差内；没有看完结果再收紧标准。

## 执行、耗时与用量

十六个业务阶段均 HTTP 200、finish_reason=stop 且收到 DONE，分析完整后才进入最终整合；本轮没有超时、断流或截断，不能据此声称历史稳定性问题已全部解决。各阶段均低于历史实验的 300 秒阈值，观测截止为 600 秒；这不表示已核查常驻服务的当前超时值。

| 指标 | 基线 | 组合 |
|---|---:|---:|
| 完整业务阶段 | 8/8 | 8/8 |
| 平均两阶段合计耗时 | 214.80 秒 | 277.24 秒 |
| 中位两阶段合计耗时 | 197.10 秒 | 259.61 秒 |
| 供应商报告 tokens | 63,486 | 75,157 |

两阶段合计不含调度开销，也不是并发实验墙钟时间；本轮组合均值比基线多约 62 秒（29%）。单次配对和推理采样波动不足以证明稳定的延迟因果关系。另有一次经验生成消耗 7,311 tokens，总计 **17 次真实调用、145,954 tokens**；不包括 Codex 复核用量，未估算账单金额。

## 后续优化方向

当前证据支持修正学习的验证方式，尚不支持继续把更多经验统一拼进提示词：

1. 在开发集上预先固定少量重复对照，区分可复现错误与一次采样波动，再判断经验的修复率；标准、评测器和预算保持不变。
2. 分别测试经验是否在相关题目触发、无关题目是否保持原行为。单位换算经验与缺失数据经验不应仅因同属基本面分析就默认全部注入；本轮尚未验证实际运行时的匹配器。
3. 将可确定的单位转换、算术和期间关系交给现有计算工具或类型化检查，以真实调用/校验结果约束回答；不要把每次算错都转成一条新自然语言禁令。先核对现有能力接入缺口，再决定最小实现。
4. 单独检验最终整合对分析错误的保留和纠正能力。本轮两处问题都传递到最终回答，仅靠经验在分析阶段生效不足以证明用户最终获益。

这些是下一轮待办，尚未实施或追加调用。本轮按登记预算停止，未通过增加重试、消耗迁移题或放宽评分制造正向结果。
